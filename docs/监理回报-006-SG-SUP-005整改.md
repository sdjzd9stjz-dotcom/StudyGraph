## A · span 缓存与原文版本

**修法（一句）**：缓存条目不再只按 `(spanId, 范围)` 索引，而是**存下写入时的原文版本**
（`Source.checksum` 或页文本的 sha256），每次读取先比版本，不一致就重算并覆盖。
提供 `loadSourceVersion` 时命中缓存连页文本都不用读（性能保住了）。

**复验输出（E05 原命令）**：

```
initial {"ok":true}
changed {"ok":false,"reason":"TEXT_MISMATCH","detail":"第 1 页 [0,1) 期望「a」实际「x」"} fresh TEXT_MISMATCH
```

**changed 行是否为 ok:false**：**是**。

**真实卡片验证（数据层，不是组件级）**：
`apps/api/src/spans/citation-integrity.ts` + `scripts/check-citation-integrity.mjs`：
扫描全部 `VERIFIED` 概念 → 按其引用的 span 读原文页文本 → 逐字符比对 → 对不上的降级为 `UNVERIFIED`。

```
① 原文未变：downgraded [] status VERIFIED
② 原文已改：downgraded ["c_card_check"] status UNVERIFIED
   failure [{"conceptId":"c_card_check","spanId":"sp_card_check","reason":"TEXT_MISMATCH",
             "detail":"第 3 页 [4,10) 期望「定积分的定义」实际「不定积分的定」"}]
```

构造方式：建 User/Canvas/Node/Source/Span（页文本放 S3 `canvas/<cv>/source/<src>/text.json`）→
Concept 先 `UNVERIFIED` → 写 `ConceptCitation` → 升 `VERIFIED`（按触发器要求的顺序）→
第一次巡检不动它 → 把原文里那句「定积分的定义」改成「不定积分的定义」→ 第二次巡检降级。

## C · registry 自检

**修法**：`planned` 由 `PLANNED_PLAN` 的键推导；自检计算四件事——
`implemented ∪ planned` 与 17 个值的**双向差集**、`implemented ∩ planned` 是否为空、
并集里是否有 17 之外的类型、注册表里是否有非 NodeType 条目。缺任何一个 → `ok:false` + 明确点名。
**启动路径**（`apps/api/src/app.ts`）调用 `selfCheck()`，不通过直接抛错拒绝启动。

**复验输出（E07 原命令）**：

三个值：`ok=false`、`problems.length=1`、`planned.includes('SOURCE')=false`。

```

## D · 适配器校验

**修法**：新增 `apps/api/src/llm/providers/validate.ts`，两个适配器共用：
`model` 必须是非空字符串、`usage` 必须是对象、`tokensIn/tokensOut` 必须是非负有限数，
否则抛 `PROVIDER_RESPONSE_INVALID`（`details.missing` 列出缺的字段）。
`cachedTokens` 是唯一可缺省项（两家厂商都是可选），缺省记 0；
`modelVersion` **只能**取响应体的 `model`，没有就报错，不回退别名。

**复验输出（E06 原命令）**：

```
extract THREW PROVIDER_RESPONSE_INVALID
method THREW PROVIDER_RESPONSE_INVALID
```

没有任何一行打印出 usage 或 modelVersion。

**正向用例（usage/model 齐全）**：

```
✔ 成功时 usage 与 modelVersion 取自厂商响应，不是本地配置
   → usage { tokensIn: 123, tokensOut: 45, cachedTokens: 100 }
   → modelVersion "gpt-4o-mini-2024-07-18"
```

**"字段不存在" ≠ "值为 0"** 的专项断言：

```
✔ D：usage 存在但缺 tokensIn → 同样拒绝（"字段不存在"≠"值为 0"）
   → PROVIDER_RESPONSE_INVALID, missing ["usage.tokensIn"]
```

## F · 漂移护栏

**修法**：用 `spawnSync` 取子进程退出码（不再用 stderr 字样启发式）。
三态：库不可达 → **2**、无漂移 → **0**、检出受保护索引 DROP → **1**。

**三个场景实测**（都不接管道，避免 `$LASTEXITCODE` 被管道污染）：

| 场景 | 命令 | 退出码 | 输出首行 |
| --- | --- | --- | --- |
| 1 库不可达 | `DATABASE_URL=...localhost:5999/nope` | **2** | `❌ 无法连接数据库，漂移未检测（migrate diff 退出码 1）` |
| 2 无漂移 | 临时删掉两条手写索引后跑 | **0** | `✅ 无漂移（schema 与库一致，手写索引未被触碰）` |
| 3 有手写索引 | 恢复索引后跑 | **1** | `❌ 漂移检测：即将删除手写索引` |

场景 1 的输出里**没有 ✅**。

场景 2 的做法：`DROP INDEX` 两条 → 跑脚本（exit 0）→ 用 guards migration 里的同一条 DDL
`CREATE INDEX IF NOT EXISTS` 恢复 → 再跑回到 exit 1。索引已确认恢复：

```
Concept_embedding_hnsw
Concept_name_trgm
