# StudyGraph · 环境安装与接续提示词

> **用途**：把 `D:\ai学习辅助工作流搭建` 这个项目交给另一台机器 / 另一个人 / 另一个 AI 继续推进时，把这份文件整份贴给它。
> **生成日期**：2026-11-19
> **读完这份之后还要读**：`StudyGraph-Agent-Prompt.md`（规格）、`docs/监理交接-状态快照.md`（进度）、`docs/runbook.md`（本机踩坑记录）

## 0. 给接手的 AI 的定位

**这个项目是三方协作的，你不是唯一参与者。** 先搞清楚你接的是哪一角：

| 角色 | 干什么 | 不该干什么 |
| --- | --- | --- |
| **监理** | 写 `docs/指令/监理指令-0NN-*.md`，定验收标准与红线 | 不写业务代码，不做验收 |
| **工程 AI** | 按指令施工，交 `docs/交付/监理回报-0NN-*.md` | 不自己改验收标准 |
| **独立验收 AI** | 按 `docs/验收/验收AI提示词.md` 核查，出判定 | 不修 bug |

**如果你是被叫来"接着搭"的，你是工程 AI。** 先去 `docs/指令/` 找**编号最大的那份指令**，那是当前任务。不要凭 README 或进度文档自己推断任务——**指令文件是唯一权威。**

## 1. 机器与软件要求

| 组件 | 版本 | 说明 |
| --- | --- | --- |
| **Node.js** | **≥ 22.11**（本机实测 26.13.1） | 需支持原生跑 `.ts` 文件、`node:test`、`process.loadEnvFile` |
| **pnpm** | **11.x**（本机 11.28.5） | `package.json` 的 `packageManager` 已锁定；可用 `corepack enable` 获得 |
| **Docker Desktop** | 29.x | 需 WSL2 后端（Windows Home 版没得选） |
| **git** | 2.x | 仓库已在 git 管理下 |
| 端口 | 3000 / 3001 / 5432 / 6379 / 9000 / 9333 | 都要空闲 |

**不需要预装**：PostgreSQL、Redis、MinIO/SeaweedFS —— 全部由 `docker-compose.yml` 拉起。

## 2. 从零到能跑：六步

### 第 1 步 · 拿代码

```bash
git clone <仓库地址> ai学习辅助工作流搭建
cd ai学习辅助工作流搭建
```

> **注意**：`课件/` 目录**不在 git 里**（`.gitignore` 排除了，体积大）。验收材料需要单独拷贝：
> 10 份 PPTX + `课本/高代.pdf` + `课本/理科数学分析.pdf`。没有它们，M2 之后的验收跑不了。

### 第 2 步 · 装依赖

```bash
corepack enable        # 如果 pnpm 不在 PATH
pnpm install
```

**如果 `pnpm install` 在 postinstall 阶段报 `EPERM`**，改用：

```bash
pnpm install --ignore-scripts
```

`pnpm-workspace.yaml` 里已经设了 `verifyDepsBeforeRun: false`，跳过 scripts 不会影响运行——Prisma 查询引擎随包体落盘，不需要 postinstall 下载。

### 第 3 步 · 起容器

```bash
docker compose up -d
docker compose ps        # 三个都要 healthy
```

| 容器 | 镜像 | 端口 |
| --- | --- | --- |
| `studygraph-postgres` | `pgvector/pgvector:pg16` | 5432 |
| `studygraph-redis` | `redis:7-alpine` | 6379 |
| `studygraph-s3` | `chrislusf/seaweedfs` | 9000（网关）/ 9333（master） |

> **为什么不是 MinIO**：`minio/minio` 已从 Docker Hub 下架，quay.io 的 token 认证在部分代理链路下恒 401，官方 Windows 二进制路径 410。SeaweedFS 的 S3 网关实现同一套协议，`ObjectStore` 层只依赖协议，换回 MinIO 只改 image 与端口，代码不用动。

**国内网络拉不动镜像时**，给 Docker 配镜像加速器（Settings → Docker Engine → `registry-mirrors`）。

### 第 4 步 · 配环境变量

```bash
cp .env.example .env
```

然后**必须改这三项**，其余保持默认：

| 变量 | 怎么填 |
| --- | --- |
| `AUTH_SECRET` | `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `BYOK_ENCRYPTION_KEY` | `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"` —— **这是用户 API key 的加密主密钥** |
| `DEEPSEEK_API_KEY` / `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` | 至少填一个；只做本地开发可以全留空，但 LLM 节点会报 `NO_MODEL_CONFIGURED` |

**`.env` 永不入库。** `.gitignore` 已排除，**不要用 `git add -f` 绕过去。**

> ⚠️ **`BYOK_ENCRYPTION_KEY` 要备份到安全地方。** 它不在数据库里，丢了之后 `UserCredential` 表里的密文全部作废，所有用户得重新录 key。

### 第 5 步 · 建库

```bash
node scripts/prisma.mjs migrate deploy --schema packages/db/prisma/schema.prisma
```

正常会依次应用这些 migration：

```
20261118030000_init                    表 / 枚举 / 外键 / 复合外键
20261118030100_guards                  CHECK / 触发器 / 视图 / 索引
20261119000000_edge_no_self_loop       CHECK（禁止自环边）
20261119000000_pending_review_enum     枚举加 PENDING_REVIEW
20261119000100_pending_review_guards   触发器参数化
20261120000000_span_region             Span 区域
```

**自检四条：**

```bash
node scripts/prisma.mjs validate --schema packages/db/prisma/schema.prisma   # → valid
node scripts/check-guards-sync.mjs                                            # → ✅ 同步
node scripts/check-drift.mjs                                                  # → 无漂移
node scripts/verify-sql.mjs                                                   # → 四条断言通过（PGlite，快速回归）
```

### 第 6 步 · 起服务

```bash
# API → 127.0.0.1:3001
node apps/api/src/server.ts

# Web → 127.0.0.1:3000（另开终端）
cd apps/web
node ../../node_modules/next/dist/bin/next build
node ../../node_modules/next/dist/bin/next start -p 3000
```

Web 还需要 `apps/web/.env.local`（已 gitignore）：

```
NEXT_PUBLIC_API_BASE_URL=http://localhost:3001
NEXT_PUBLIC_DEV_PAT=<本地开发的 Personal Access Token>
STUDYGRAPH_DEV_PAT=<同上>
```

## 3. 验收自己装对了没有

按顺序跑，**每条都要有输出**。任何一条失败，先别往下走。

```bash
# 1. 环境自检（012 起提供）
node scripts/env-check.mjs
# 期望：docker / postgres / redis / s3 / key 全部 OK

# 2. 契约测试
node packages/contracts/test/ports.test.ts
# 期望：27 pass

# 3. DAG 单测
node apps/api/test/unit/dag.test.ts

# 4. 执行器注册表自检
node scripts/registry-self-check.mjs

# 5. 对象存储往返
node scripts/s3-roundtrip.mjs
# 期望：put → get → sha256 一致 → delete → 读不回

# 6. 全量复验（011 起提供）

# 环境不全时给 SKIP 并非 0 退出 —— SKIP 不等于 PASS。
```

## 4. 这台机器上的坑（**换机器请先确认是否适用**）

`docs/runbook.md` 里记了 6 个坑，**它们大半是"原机器沙箱环境"特有的，不是项目本身的缺陷**。接手的人先分清：

| 坑 | 原机器现象 | **换机器后还要不要管** |
| --- | --- | --- |
| 1 · 工作区缺 `WRITE_OWNER` | shell 一启动就 `SetNamedSecurityInfoW failed` | ❌ **不用**。DSH 沙箱的 ACL 问题 |
| 2 · 沙箱不允许管道式子进程 | `pnpm install` / `node --test <目录>` 报 EPERM | ❌ **不用**。正常机器直接跑 |
| 3 · pnpm junction 找不到模块 | `Cannot find module '@prisma/engines'` | ⚠️ **可能不用**。`nodeLinker: hoisted` 对 Windows 普遍更稳，保留无害 |
| 4 · `confbox` 子路径断裂 | `prisma` CLI 启动即 `ERR_PACKAGE_PATH_NOT_EXPORTED` | ⚠️ **看版本**。`overrides.confbox: 0.3.2` 已写死，跟着仓库走 |
| 5 · Prisma CLI 输出在管道下丢失 | 命令成功但一个字不打印 | ⚠️ **可能不用**。`scripts/prisma.mjs` 已改成 `stdio: 'inherit'`，通用修法，保留 |
| 6 · 工作区内不能删文件 | `Remove-Item` 被拒 | ❌ **不用**。DSH 的拒绝项 |

> **一句话**：坑 1、2、6 是原机器的沙箱限制，换机器自动消失；坑 3、4、5 的修法已写进配置文件，跟着仓库走即可，**不要"清理"它们**。

**真正通用的注意事项只有这三条：**

1. **`migrate dev` 会删手写索引** —— Prisma 推不出 `Concept_embedding_hnsw`（HNSW）与 `Concept_name_trgm`（gin_trgm_ops），`migrate diff` 会生成两行 `DROP INDEX`。**日常只用 `migrate deploy`；用 `migrate dev` 必须人工检查生成的 SQL 并删掉那两行。** 提交前跑 `check-drift.mjs`。
2. **不要通过包名 import `@studygraph/contracts`** —— Node 对 node_modules 内的 `.ts` 直接报 `ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`。用相对路径直连 `packages/contracts/src/index.ts`。
3. **`.env` 与 `课件/` 永不入库**，`.env.example` 必须保持为空占位。

```
StudyGraph-Agent-Prompt.md      ← 规格唯一来源（只读保护，改前 attrib -R，改后 attrib +R）

  ├─ 指令/                       ← 监理指令 001–012，编号最大的是当前任务
  ├─ 交付/                       ← 工程方回报
  ├─ 验收/                       ← 独立验收报告 + 证据
  ├─ 监理交接-状态快照.md         ← 进度、欠账、红线（新会话必读）
  ├─ 环境安装与接续提示词.md      ← 本文件

  ├─ architecture.md
  └─ milestone-1.md / milestone-2.md
apps/
  ├─ api/                       ← Fastify，Node 原生跑 .ts
  └─ web/                       ← Next 14 App Router
```

## 7. 这个项目特有的红线

写在规格里，但接手的人最容易违反：

| 红线 | 含义 |
| --- | --- |
| **溯源是物理约束** | 没有 span 引用的资产不得标记 `VERIFIED`（有触发器拦） |
| **执行必须显式触发** | 上游改了只标 stale，不许自动重跑下游 |
| **写作类节点只给骨架** | 不许直接生成成段正文 |
| **判据不许悄悄放宽** | 缓存键必须覆盖判定函数的**全部**输入；产物必须存"依据"不只存"结果" |
| **宁可 10 张真卡，不要 15 张假卡** | 数量不够可以说，凑数不行 |
| **API key 只进不出** | 加密落库，响应只给 `last4`；超时不许判 key 失效 |

## 8. 环境自检不通过时

| 现象 | 先查什么 |
| --- | --- |
| `docker compose ps` 没有 healthy | Docker Desktop 是否启动；引擎管道是否存在 |
| 拉镜像超时 | 镜像加速器 / 代理 |
| `prisma` 命令报 `ERR_PACKAGE_PATH_NOT_EXPORTED` | `pnpm-workspace.yaml` 的 `overrides.confbox` 是否还在 |
| `Cannot find module '@prisma/engines'` | `nodeLinker: hoisted` 是否还在 |
| `migrate deploy` 报 `22P02 invalid input value for enum` | 是不是跳过了中间某个 migration |
| LLM 节点报 `NO_MODEL_CONFIGURED` | `.env` 里三个 key 是否全空 |
| LLM 调用 401 | key 是否过期；**不要**因此把 key 判成永久失效 |

交给别人之前，确认这些**没有跟着仓库走**，需要单独传输：

| 项 | 为什么 |

| 未提交的改动 | 交接前 `git status` 确认为空，或者说明为什么留着 |
