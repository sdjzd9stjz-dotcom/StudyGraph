## 5. 🔴 当前唯一的技术分歧：7 张卡

### 事实

```
27 条候选 claim → 只有 7 条通过校验 → 7 张卡
目标 15，材料不足时的下限 10。**两个都没到。**
```

### 原因（工程方 010/013 自述）

010 引入了一条**保守规则**：自动确认要求「逐字摘录」——定义与引文完全相等、名称与解释同在、排除纯标题。不满足即标为待核验。

**20 条候选被这条规则拦下**，理由是「标题、自述与原文不逐字相等、名称与证据无法按当前规则对齐」。

### 工程方自己的诚实说明（013）

> "本轮不能证明材料最多只有 7 条有效论断；不据此放宽门槛。"
> "语义等价的改写也可能进入待核验；逐字与句式检查不能取代独立的人工语义抽查。"

### 我的判断：这是个**真问题**，不是敷衍

两边都成立：

- **规则严是对的**：逐字相等是唯一可机械验证的标准，放宽就有造假空间
- **但 22 字/页 的 PPT 材料，定义本来就不会逐字重复**：老师写的是「连续函数：在区间上每一点都连续」，模型抽出来可能是「在区间上每一点都连续的函数称为连续函数」——语义相同，字面不同

**这不是工程方偷工，是「机械可验证」与「材料特性」之间的真实冲突。**

### 三条出路（需要用户拍板或我下一份指令定）

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| **A. 分层校验** | 逐字相等的 → 自动 VERIFIED；语义等价但非逐字的 → 标 `PENDING_REVIEW`，不自动拒绝也不自动通过 | 需要新状态值，M1 schema 要 migration |
| **B. 放宽到"词元重叠率"** | 定义与原文的词元重叠 ≥ 阈值即通过 | 可机械执行，但阈值要校准，且仍可能放过改写 |
| **C. 承认"7 张是这份材料的真实上限"** | 正式把 M2 的数量门槛下调到 7，写进规模偏离备案 | 需要用户批准规格变更；且要证明"不是规则太严" |

**我倾向 A。** 理由：`PENDING_REVIEW` 既保住机械验证的严格性，又不把语义等价的内容直接扔掉。它的代价是引入人工复核流程——但这恰好对应产品定位（教师能不能敢用）。

**这条必须在下一轮指令里定。** 目前尚未写进任何指令。

## 10. 已识别的高频陷阱（专属本项目）

| 陷阱 | 识别方式 |
| --- | --- |
| **用身份代替内容做判定** | span 缓存用 `(id,page,区间)`、source 指纹用 `path`——**两个 P0 同一个错误** |
| **只问"有没有"不问"是不是人话"** | 劣质 OCR 的乱码能通过 span 校验 |
| **静默截断** | `chunk` 吞字符、CTE `depth < 64`、视图返回空数组 |
| **护栏自身静默降级** | `check-drift.mjs` 连不上库却报"无漂移" |
| **缓存把校验函数变成恒真函数** | 判定函数的输入没全部进缓存键 |
| **前端拦、后端不拦** | curl 绕开 UI 直测 |
| **单层 stale** | 造 A→B→C，改 A 查 C |
