# docs 目录说明

按**角色**分三类，一类一个文件夹；项目自身的长期文档留在根目录。

```
docs/
├── 指令/    监理下发的指令（SG-SUP-00N），对规格的细化与补充，只读
├── 交付/    工程方提交的整改/交付回报（监理回报-00N），一轮一份
├── 验收/    独立验收的判定、证据与验收提示词
├── architecture.md   已锁定的实施决策与不变量
├── structure.md      目录结构与文件职责
├── runbook.md        本机环境、启动、迁移、排错
├── milestone-1.md    M1 记录（已验证行为 + 未完成项）
└── milestone-2.md    M2 记录
```

## 三类文件的对应关系

同一个编号串起一轮：`指令/监理指令-00N-*.md` → `交付/监理回报-00N-*.md` → `验收/独立验收-00N-*.md`

## 约定

收到监理回报时按独立验收流程核验。用户明确说“由你来解决”时，负责修复、复测，并在 `交付/` 提交本轮工作报告，列出工程 AI 的改动、证据、实际效果和未完成项。工程自测与独立验收分别署明。

- **指令只读**：不改监理下发的内容；有异议写进对应的「交付」回报。
- **交付不回头改**：一轮的回报定稿后不再修改，新结论写进下一轮回报。
- **路径引用**：跨文件夹引用用相对路径（例如 `验收/` 里引用交付文件写 `../交付/xxx.md`），
  根目录文档引用则写 `docs/交付/xxx.md`。
