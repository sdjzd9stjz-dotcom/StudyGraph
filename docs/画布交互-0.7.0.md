## 1. 重写了什么

旧的 `CanvasEditor.tsx`（277 行）只有拉一条侧栏 + ReactFlow，空画布时是一堆状态文字。
现在拆成 `apps/web/components/canvas/` 下四个组件：

| 组件 | 职责 |
| --- | --- |
| `CanvasWorkbench.tsx` | 画布主体、右键、连线、分组、协调 |
| `SgNode.tsx` | 节点：双栏 + 悬停提示词窗 |
| `ContextMenu.tsx` | 右键菜单 + 悬停子菜单 |
| `Sidebar.tsx` | 左侧技能 / 节点面板 |
| `AssistantBar.tsx` | 底部 AI 对话栏 |

## 2. 五点要求逐条验收

### ① 空画布 + 侧栏 skill

```
空画布提示: true
侧栏存在: true
侧栏技能: chinese-math-notation, citation-strict
侧栏常用节点: SOURCE, CHUNK, EXTRACT, CARD, PREREQ, REVIEW
```

侧栏分两段：技能在上（拖到节点上绑定），节点在下（常用 6 个）。
其余 11 个节点收在「高级节点 (11)」折叠区，不删除。

### ② 右键菜单 + 悬停子菜单

```
右键菜单出现: true
"新建节点"项存在: true
子菜单初始隐藏: true
悬停后子菜单出现: true
可选类型数: 17
建节点后数量: 1
```

空白处右键 → 「新建节点」→ 鼠标移上去 → 右侧展开 17 种类型（常用在前、高级在后，
每个带一句人话提示）。节点上右键 → 运行 / 重命名 / 复制 / 删除 / 打包。

### ③ 节点精简

侧栏默认只显示 **6 个**：课件 / 切片 / 概念 / 知识卡 / 先修 / 复习。
这是一条能跑通的链，每个都有中文名与一句说明。

### ④ 底部 AI 对话栏

```
面板自动展开: true
回复: 我建议2个节点：课件 → 知识卡。确认后它们会以草稿状态放上画布，
      **不会自动执行**——需要你逐个点运行。
应用按钮: true
应用后节点数: 2
```

**不自动执行**是刻意的：执行会消耗用户的模型额度，必须由人发起。

**离线也能用**：没有模型密钥时走规则引擎，`把课件做成知识卡` 这类需求能直接映射成
标准链（课件 → 切片 → 概念 → 知识卡 → 先修）。理由不是凑合——
新用户的第一步就是想把这几个东西串起来，让它依赖密钥等于让人卡在第一步。

### ⑤ 节点双栏，提示词窗悬停才显示

```
提示词窗默认: false   （收起）
悬停后: true          （展开）
输出栏: true          （常驻）
```

提示词窗常驻会把节点撑成一面墙，一屏放不下几个节点，就失去了"看思维链条"的意义。

## 3. 分组：把一组节点打包成上下文

用户要求「可以使用特定功能将一部分节点打包并整理成一个节点用来做其它节点的上下文」。

**没有做成新的节点类型**——分组不执行、不产出 Artifact，它只是「这几个节点的产物一起看」。
数据结构是三张表（`NodeGroup` / `NodeGroupMember` / `NodeGroupLink`）：

- 框选多个节点 → 右键「打包这 N 个节点」→ 输入名字
- 画布上出现虚线框卡片，可折叠
- 别的节点可以把这个组当上下文引用（`POST /v1/groups/:id/link`）
- 解组只删组，不删节点

接口已验证（建组、列出、解组），**界面上的链接操作尚未做完整验收**。

## 4. 途中修的三个真 bug

| 问题 | 症状 | 原因 |
| --- | --- | --- |
| 节点标题显示 `文件解析` | AI 建出来的节点名不对 | 用了旧的 `NODE_TYPE_LABELS` 而不是新的友好名 |
| 两个节点叠在一起 | 卡片互相遮挡 | 布局间距 220 < 节点宽度 232 |
| AI 回复看不见 | 点了发送没反应 | 回复渲染在 `{open && …}` 里，发送时没展开面板 |

第三个是**测试方法救了命**：直接 curl 接口完全正常，说明问题在前端。
如果只看接口返回，会得出"功能正常"的错误结论。

## 5. 双击搜索与端口拖拽（0.8.0 补上）

上一版漏了 ComfyUI 的两个核心效率手段，现已实现并实测。

### 双击空白 → 节点搜索

照 ComfyUI：输入框自动聚焦、首项默认选中、↑↓ 选择、Enter 确认、Esc 关闭。

```
双击后搜索面板: true
输入框已聚焦: true
选项总数: 17
搜"知识"后选项: EXTRACT,CARD,PREREQ
建后节点数: 1
```

### 端口拖到空白处 → 只列能接上的节点，选中后自动连线

```
起点: 1283 496 → 终点: 1063 560
搜索面板: true
限定可选类型: PREREQ,QUIZ
提示: 能接 CARD.out 的节点…
选后: nodes 2→3, edges 0→1
库里边数: 1 | 边: out→in
```

从「知识卡」的输出口拖出来，只列出 **PREREQ 和 QUIZ** —— 因为只有这两个节点有
该类型的输入端口。判定复用 `contracts/validateConnection`，与手工连线、
服务端校验是同一套，不另写一份类型兼容表。

### 边界情况

```
双击节点时不弹搜索: true    ← 那是重命名的位置
双击空白时弹搜索: true
Esc 关闭: true
```

### 踩的坑：事件在冒泡阶段被吞掉

前两次尝试都失败——`onDoubleClick` 透传不到，容器上的冒泡监听也收不到。
最后定位到：**ReactFlow 的 pane 自己处理双击（双击缩放）并在冒泡阶段
`stopPropagation`**。改用捕获阶段 `addEventListener('dblclick', handler, true)` 才生效。

判断「是不是点在空白处」也从 `classList.contains('react-flow__pane')` 改成
`target.closest('.react-flow__node')` 取反 —— pane 内部还有 renderer / viewport 等
子元素，事件目标取决于点在哪儿，用 class 判断不可靠。

## 6. 拖线经过节点时的高亮（0.9.0）

拖线时实时告诉用户"哪些节点能接、哪些不能"，这是 ComfyUI 里最直接的防错手段。

三种状态：

| 状态 | 视觉 |
| --- | --- |
| `origin` 起点自己 | 不变 |
| `compatible` 能接上 | 绿色描边 + 外发光 + 放大 1.03 + 右上角「可接入」徽标 |
| `incompatible` 接不上 | 压到 40% 不透明度（不隐藏，用户仍能看见它在哪） |

### 实测

```
拖线前: CARD:none | CARD:none | PREREQ:none
拖线中: CARD:origin | CARD:incompatible | PREREQ:compatible
可接入徽标数: 1
松手后: CARD:none | CARD:none | PREREQ:none
```

第三行同样重要：**松手后高亮必须全部撤销**，包括连到空白处弹出搜索面板之后。

### 踩的坑：`overflow: hidden` 把端口裁掉了

第一版加了高亮但拖线完全没反应。排查过程：给 handle 打点计数，发现
`pointerdown` 计数是 0——**按在端口上，事件根本没落到端口**。

原因是我给节点根元素加了 `overflow: 'hidden'`（为了圆角裁剪）。ReactFlow 的端口是
跨在边框线上的（一半在内一半在外），被裁掉后实际可点区域只剩一半，
`elementFromPoint` 命中的是画布而不是端口。

**修法**：根元素不能 `overflow: hidden`；圆角裁剪交给内部块自己处理。

这条记在这里是因为它很隐蔽：界面上端口看起来完全正常，只是"点了没反应"。

## 7. 拖动端口：具体到“哪一根口能接”（0.10.0）

节点级高亮只能整体变色；一个节点有多个端口时，用户仍要自己判断该往哪根松手。现在改成端口级。

| 状态 | 视觉 |
| --- | --- |
| `ok` | 端口放大到 15px、绿色填充 + 白边 + 绿环外发光 |
| `no` | 端口透明度压到 22% |
| 无状态（未在拖线） | 原样 |

### 关键设计：接不上的节点，端口也逐个标出来

早期实现只给‘能接上的节点’标端口，于是接不上的节点只有一个整体变暗的方块，
用户看不出“是这根口不行”。现在对所有非起点节点都计算端口状态。

### 实测

用三节点验证：`CARD`（输出 ConceptCardSet）、`PREREQ`（输入 ConceptCardSet，能接）、
`METHOD`（输入 ProblemInput/external + SolutionTrace，接不上）。

```
拖线前端口: CARD[-/-] | PREREQ[-/-] | METHOD[-/-]
拖线中端口: CARD[-/ok] | PREREQ[ok/-] | METHOD[no/-]
松手后端口: CARD[-/-] | PREREQ[-/-] | METHOD[-/-]
```

读法：`[输入口状态/输出口状态]`。

- `CARD[-/ok]`：起点自己的输出口亮起
- `PREREQ[ok/-]`：能接的输入口亮起
- `METHOD[no/-]`：接不上的输入口压暗
- 松手后全部清空

### 实现要点

`allowedForPort` 除了返回"哪些类型能接"，还返回 `portsByType: Map<类型, 端口名[]>`。
判定仍然复用 `contracts/validateConnection`，与手工连线、服务端是同一套。
