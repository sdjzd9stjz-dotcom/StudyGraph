## 0. 先读这三段（不读会重复踩坑）

**① 这个项目被打回过三次，没有一次是因为不会写代码。**
三次全是「验证的不是系统行为」：缓存键漏输入、指纹只用路径、迁移硬编码了实体没有的枚举值。
所以本项目的纪律是：**每条「已完成」必须能回答「删掉这条断言，什么 bug 会漏」**，
证据必须是可粘贴的终端原文，不接受「测试全过」。

**② 中文路径是这台机器上的硬约束。**
`D:\ai学习辅助工作流搭建` 含中文，导致：
- `npm i electron` 的 postinstall 解压**静默失败**（只落一个文件），
- Electron 二进制在中文路径下**启动即崩**（`0xC0000005`）。

凡是「装了但跑不起来」「解压缺文件」，先怀疑路径，不要怀疑代码。
Electron 二进制已从纯 ASCII 路径手工搬进来，见 §5。

**③ `VERIFIED` 为 0 是用户拍板的预期结果，不是缺陷。**
T1 要求 `definition === quote` 逐字相同，而提示词要求模型转述，两者刻意不重叠。
`VERIFIED` 只能由人工复核产生。**不要为了让数字好看去松判据**（用户已明确「选 A」）。

## 1. 项目是什么

面向大学生的节点式 AI 学习工作流平台。学生在画布上把课件变成可溯源的知识卡、方法卡、题目。

- **规格唯一来源**：`StudyGraph-Agent-Prompt.md`（**只读文件**，改前 `attrib -R`，改完 `attrib +R`）
- **技术栈**：Next 14 App Router + Fastify + Prisma 6.19.3 + PG16/pgvector + BullMQ/Redis + S3(SeaweedFS)
- **17 个节点类型**；17 个 domain model
- **五条硬约束**：溯源是物理约束 / 执行必须显式触发 / 写作类只给骨架 / 出题必须过三检 / 干扰项必须诊断错因

## 4. 项目里最容易踩的六个坑（全都踩过）

| 坑 | 表现 | 正确做法 |
| --- | --- | --- |
| **共享触发器硬编码枚举值** | `Problem` 用 `ProblemStatus`（无 `PENDING_REVIEW`），一执行 22P02 | 状态集按实体传参：Concept/Method → 降 `UNVERIFIED`；Problem → 降 `PENDING` |
| **校验器自己静默降级** | `check-guards-sync.mjs` 按 `;` 切分，把 `$$` 函数体切断，函数整条丢失 | 已修：认 dollar-quote + 剥注释前缀；有 8 条反向自测 |
| **测试自身污染被测对象** | 巡检用例共用一个 span，G 改文本把 A/C 一起打成 TEXT_MISMATCH | 每个用例独立画布/来源/页文本/span |
| **高亮定位错** | M2 的 span 是「整页一片」（0–49），按 span 区间高亮 = 整页标黄 | 高亮 `ConceptCitation.quote` 在页内的位置，不是 span 区间 |
| **`NEXT_PUBLIC_*` 是构建期内联** | 桌面版端口运行时才定，写进构建产物等于写死 | 服务端读 `STUDYGRAPH_API_BASE_URL`，作为 prop 传给客户端组件 |
| **中文路径 + Electron** | 解压失败 / 启动即崩 `0xC0000005` | 从 ASCII 路径搬二进制；打包产物也要在 ASCII 路径下跑 |
| **standalone 的 static 放错层** | 页面 HTML 正常、看着"渲染了"，但所有 JS/CSS 404 → **客户端永不水合 → 按钮点了毫无反应**（2026-11-21 用户实际遇到：点「新建画布」没反应） | static 与 public 要复制到 `standalone/apps/web/` 下面，不是 `app-build/apps/web/.next/`。判断方法：CDP 里看 `发起的请求` 是否为空 —— 空就是没水合，不是接口问题 |
| **客户端组件用模块常量 API_BASE_URL** | 浏览器 bundle 里它被求值成 `http://127.0.0.1:3001`，桌面版随机端口永远对不上 | 由服务端求值后作为 `apiBaseUrl` prop 传进客户端组件 |

另外两条项目红线：**不许用 PGlite 冒充真实 PG 的验收证据**；**不许降 `strict` 换 tsc 绿灯**。
