## 4. 项目里最容易踩的六个坑（全都踩过）

| 坑 | 表现 | 正确做法 |
| --- | --- | --- |
| **共享触发器硬编码枚举值** | `Problem` 用 `ProblemStatus`（无 `PENDING_REVIEW`），一执行 22P02 | 状态集按实体传参：Concept/Method → 降 `UNVERIFIED`；Problem → 降 `PENDING` |
| **校验器自己静默降级** | `check-guards-sync.mjs` 按 `;` 切分，把 `$$` 函数体切断，函数整条丢失 | 已修：认 dollar-quote + 剥注释前缀；有 8 条反向自测 |
| **测试自身污染被测对象** | 巡检用例共用一个 span，G 改文本把 A/C 一起打成 TEXT_MISMATCH | 每个用例独立画布/来源/页文本/span |
| **高亮定位错** | M2 的 span 是「整页一片」（0–49），按 span 区间高亮 = 整页标黄 | 高亮 `ConceptCitation.quote` 在页内的位置，不是 span 区间 |
| **`NEXT_PUBLIC_*` 是构建期内联** | 桌面版端口运行时才定，写进构建产物等于写死 | 服务端读 `STUDYGRAPH_API_BASE_URL`，作为 prop 传给客户端组件 |
| **中文路径 + Electron** | 解压失败 / 启动即崩 `0xC0000005` | 从 ASCII 路径搬二进制；打包产物也要在 ASCII 路径下跑 |

另外两条项目红线：**不许用 PGlite 冒充真实 PG 的验收证据**；**不许降 `strict` 换 tsc 绿灯**。

## 5. 桌面客户端现状（最重要的一节）

### 5.1 已经跑通的

```

→ dist-desktop/<时间戳>/StudyGraph/StudyGraph.exe   （约 504MB）
```

产物结构：

```
StudyGraph.exe
resources/app/main.cjs              ← 桌面主进程
resources/app-build/
    apps/api/dist/…                 ← API 编译产物（scripts/build-api.mjs）
    apps/web/.next/standalone/…     ← Next 独立产物
    apps/web/.next/static           ← 必须单独复制，否则无样式
    node_modules/                   ← 只为 API 装的生产依赖（94 个包）
```

**已验证**：把产物复制到 ASCII 路径（`C:\tmp\sg-pkg\StudyGraph\`），旁边放一份 `.env`
（只含 `DATABASE_URL` 与 S3 五项 + `AUTH_SECRET`），双击能启动、窗口能渲染、26 个画布全部显示。
截图证据：`.tmp-backup/packaged-smoke.png`。

主进程做的事：找两个空闲端口 → 用 Electron 自带的 Node 起 API 与 Next → 等 `/health` 与 `/` 都通 → 开窗口 → 退出时收子进程。

### 5.2 还没做的（下一步的主任务）

**① 内置 PostgreSQL（用户明确要求，这是桌面版的本质）**

现在是「桌面壳 + 外部 Docker PG」，还不算真正的桌面软件。要做的：

1. 首次启动把便携版 PG16 释放到 `%LOCALAPPDATA%\StudyGraph\pgsql`
2. `initdb` → `CREATE EXTENSION vector` → 应用 7 份 migration
3. 主进程 `resolveDatabase()` 返回内置库的连接串（函数已经留好，在 `apps/desktop/main.cjs`）
4. 卸载时提供「保留 / 删除数据」选项

**pgvector 是必须的**：迁移里有 `CREATE EXTENSION "vector"`，`Concept.embedding` 是 `vector(1536)`。
所以只有两条路：

| 方案 | 评价 |
| --- | --- |
| **内置真实 PostgreSQL 16 + 编译好的 pgvector**（推荐） | 本机有 Visual Studio 18 Community，编译条件具备；包体增加约 150–250MB |
| PGlite（WASM） | **不建议**：pgvector 在 PGlite 上是实验性的，且手册明令禁止拿它当验收证据 |

**② 打包成单文件安装包**：现在是目录形态 + 手工复制。需要 Inno Setup 或 NSIS 做成 `.exe` 安装器（开始菜单快捷方式、卸载项、数据目录清理）。

**③ 对象存储本地化**：现在 S3 还依赖 Docker 的 SeaweedFS。桌面版应加一个 `kind: 'local'` 的 `ObjectStore` 实现（写到用户数据目录），接口已经是现成的。

**④ 首次启动向导**：填 DeepSeek key（走 BYOK 加密落库）、选数据目录。

### 5.3 桌面上要小心的事

- **端口不能写死**：学生机器上 3000/3001 常被占用，主进程已经用动态端口，别改回去
- **Electron 33 内置 Node 20.18**：没有 `--experimental-strip-types`，**只能跑编译后的 .js**
- **中文路径**：产物若放在含中文的目录，exe 起不来
- **`.env` 查找顺序**：安装目录旁 → `%APPDATA%/StudyGraph/.env`；打包后不读开发者仓库的 `.env`
