## 2. 端口矩阵定稿（17 × 输入/输出）

判定规则只有一条：**`from` 端口类型必须与 `to` 端口类型同名**。
⤓ = 入口端口，数据来自画布外部，不允许被连线灌入。

| # | type | 输入 | 输出 |
| --- | --- | --- | --- |
| 1 | `source` | —（文件由上传提供） | `out` → SourceDoc |
| 2 | `chunk` | `in` ← SourceDoc | `out` → ChunkSet |
| 3 | `extract` | `in` ← ChunkSet | `out` → ConceptClaims |
| 4 | `card` | `in` ← ConceptClaims | `out` → ConceptCardSet |
| 5 | `prereq` | `in` ← ConceptCardSet | `out` → GraphPatch |
| 6 | `quiz` | `in` ← ConceptCardSet | `out` → ProblemSet |
| 7 | `grade` | `in` ⤓ AnswerRecord | `out` → GradeResult |
| 8 | `review` | `in` ← GradeResult | `out` → ReviewPlan |
| 9 | `gate` | `in` ← ProblemSet | `out` → ProblemSet |
| 10 | `probe` | `problem` ⤓ ProblemInput | `out` → ProbeProfile |
| 11 | `method` | `problem` ⤓ ProblemInput，`solution` ← SolutionTrace | `out` → MethodCard |
| 12 | `solve` | `problem` ⤓ ProblemInput | `out` → SolutionTrace |
| 13 | `diagnose` | `in` ← GradeResult | `out` → Diagnosis |
| 14 | `variant` | `in` ← ProblemSet | `out` → ProblemSet |
| 15 | `distractor` | `in` ← ProblemSet | `out` → ProblemSet |
| 16 | `check` | `in` ← ProblemSet | `out` → VerifiedProblems |
| 17 | `paper` | `in` ← VerifiedProblems | `out` → PaperSpec |

终端产物（GraphPatch / ProbeProfile / ReviewPlan / Diagnosis / MethodCard / PaperSpec）不连下游：
它们落库或进卡片库，不是边上的中间态。

### 2.1 必须 400 的负向用例

| # | from | to | errorCode |
| --- | --- | --- | --- |
| N1 | `source.out`(SourceDoc) | `card.in`(ConceptClaims) | `EDGE_PORT_TYPE_MISMATCH` |
| N2 | `chunk.out`(ChunkSet) | `paper.in`(VerifiedProblems) | `EDGE_PORT_TYPE_MISMATCH` |
| N3 | `extract.out`(ConceptClaims) | `check.in`(ProblemSet) | `EDGE_PORT_TYPE_MISMATCH` |
| N4 | `card.out`(ConceptCardSet) | `chunk.in`(SourceDoc) | `EDGE_PORT_TYPE_MISMATCH` |
| N5 | `chunk.out`(ChunkSet) | `solve.problem`(ProblemInput ⤓) | `EDGE_PORT_EXTERNAL` |

### 2.2 正例（防止"全拒绝也算通过"）

P1 `source→chunk`、P2 `chunk→extract`、P3 `extract→card`、P4 `card→prereq`、P5 `card→quiz`、
P6 `solve→method.solution`、P7 `variant→check`、P8 `check→paper`；
另有 `quiz→gate`、`quiz→variant`、`distractor→check`、`grade→review`、`grade→diagnose` 一并覆盖。

## 3. 矩阵被单测逼着改了两处（诚实记录）

写断言时发现上一版（`docs/milestone-1.md` 初稿）有两处硬伤，**已修正并说明为什么**：

### 3.1 `ProblemInput` / `AnswerRecord` 没有生产节点

初稿写了 `P5 problem.out → solve.problem`，但 17 个节点里**没有任何节点产出 `ProblemInput`**——
题面是学生粘贴/拍照进来的，不来自上游节点；`AnswerRecord` 同理（作答提交）。

不改的后果：这条边永远拿不到数据，是死边；后端一旦允许，前端就会画出一条指向空槽的连接线。

处置：引入**入口端口**标记（`PortSpec.external`），向入口端口连线返回
`EDGE_PORT_EXTERNAL`（400），UI 渲染成"上传/粘贴槽"。并加了一条结构性断言：
**凡标了 external 的端口，其类型不得被任何节点产出**（防止以后有人加了生产节点却忘了摘标记）。

### 3.2 N3 的错误码变了

初稿 N3 是 `extract.out → grade.in`，期望 `EDGE_PORT_TYPE_MISMATCH`。
`grade.in` 变成入口端口后，判定顺序变成"先入口、后类型"，返回的是 `EDGE_PORT_EXTERNAL`——这才是真实原因。
所以 N3 换成 `extract.out → check.in`（纯类型不匹配），入口端口单独作为 N5。

> 判定顺序写死在 `validateConnection()`：端口存在 → 是否入口 → 类型是否相同。
> 服务端与前端用的是同一个函数，不存在两边顺序不一致。

## 6. 工程约束（踩坑后写进 runbook §4.1 的三条）

1. **单测直接跑文件**：`node --test <目录>` 会 spawn 子进程，本机沙箱下 EPERM。
2. **不能按包名 import `@studygraph/contracts`**：Node 的类型剥离拒绝 node_modules 内的文件
   （`ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`），pnpm 的 workspace 链接正好解析到那里。
   M1 阶段 `dag.ts` 用相对路径直连 `packages/contracts/src/index.ts`，M2 上 tsc 构建后改回包名。
   > 我先试过 `imports` 映射（`#contracts`），Node 不允许 target 跳出包根，报 `ERR_INVALID_PACKAGE_TARGET`。

   不是"单测框架选型"，M2 再定。

## 7. 环境：数据库仍然没有，理由和昨天不是同一个

| 事实 | 证据 |
| --- | --- |
| Docker 未安装 | `Get-Command docker` 空；`C:\Program Files\Docker` 不存在 |
| WSL 未安装 | `wsl --status` → 提示先 `wsl --install` |
| 机器是 Home 版 | `ProductName = Windows 10 Home China`，无 Hyper-V，Docker 必须走 WSL2 |
| 安装包未下完 | `D:\docker-installer\DockerDesktopInstaller.exe` = 568,637,763 / 623,969,712 字节 |
| 下载中断原因 | 经代理的 HTTP/2 流在 ~500 MiB 被重置（`ResponseContentLengthMismatchError`），已改 HTTP/1.1 + Range 续传 |
| **代理进程已退出** | `127.0.0.1:7897` 未监听，无 clash/mihomo/v2ray 进程 |
| 直连被中间人 | `desktop.docker.com` → `205.164.50.x`，证书 issuer `Scholar Root CA v1` / `Scholar Verify` |
| npm 源未被劫持 | `registry.npmjs.org` 是 Cloudflare + Google Trust Services 正常证书 |

也就是说：**网络侧需要你先做两件事**，我这边只能等。

1. **启动你的代理客户端**（`7897` 现在没人监听）。起来之后我能续传剩下 55 MiB。
2. **管理员执行**（Home 版绕不过 WSL2）：

```powershell
netsh winhttp set proxy 127.0.0.1:7897   # 让 WSL/Windows Update 也走代理
wsl --install --no-distribution
# 重启
```

装完 Docker Desktop 后撤销系统级代理：`netsh winhttp reset proxy`

> 顺带：`winget` 报 `0x80072F0D` 也是同一根因（WinINet 不走代理 → 直连 → 撞 Scholar 证书）。
> 打开代理客户端的"系统代理"开关后 winget 就能用，不必改注册表。
