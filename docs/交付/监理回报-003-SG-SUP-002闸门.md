```
   DROP INDEX "Concept_name_trgm";

   Prisma 无法从 schema.prisma 推出它们，所以 diff 会把它们当成多余的。
   处理方式：从生成的 migration 里删掉这些 DROP INDEX 行，再执行 migrate deploy。

```

同时按 §2.3 的要求写进了 `docs/runbook.md` §4.2：日常只用 `migrate deploy`，
`migrate dev` 生成的 migration 必须人工检查、见到 `DROP INDEX` 就删。

**为什么不做根修**（把索引写进 schema.prisma）：Prisma 6 没有 HNSW 索引类型；
`gin_trgm_ops` 虽可用 `ops: raw(...)` 表达，但索引已存在，再让 Prisma 生成一次 `CREATE INDEX` 会撞名。
根修要等一个可以安全重建索引的窗口（M2 建库脚本一并处理）。这一点写进了脚本头注释。

## 4. P1-1：stale 只沿 `DERIVED_FROM`（采纳你的推断）

### 4.1 结论与理由

**采纳**，写入 `docs/architecture.md` §4.0：

| 边 | 为什么不该触发 stale |
| --- | --- |
| `CITES` | 引用的是 `Span`，不是上游节点的产物。原文是否变化由 `Source.checksum` 与 span 校验判定；上游重跑不改变被引用的原文，没有理由让下游重算 |
| `PREREQUISITE` | 它是知识结构（学习路径顺序），不是数据流。沿它传播会让"补一条先修边"这种纯知识操作把整条加工链标脏——既烧钱，又给学生"我的卡片坏了"的错误信号 |

### 4.2 两边怎么对齐的

- `dag.ts`：`STALE_EDGE_KINDS = ['DERIVED_FROM']`，`collectDownstream` / `collectUpstream` / `topoSort` 默认用它；
  需要看全部关系时显式传 `ALL_EDGE_KINDS`
- `downstream.sql`：本来就是 `AND e.kind = 'DERIVED_FROM'`，未改语义，只补了 `depth` / `truncated` 两列

> 顺带修正一处旧错误：上一版 SQL 头注释写着"与纯函数互为验证"，但两边默认集合不同，
> 那句话当时是假的。现在它有测试兜着才成立。

### 4.3 等价性测试（真库，不是 PGlite）

`apps/api/test/integration/downstream-equivalence.test.ts`
同一张图（**含 CITES 与 PREREQUISITE 边**）：

```
n_a --DERIVED_FROM--> n_b --DERIVED_FROM--> n_c
n_a --CITES--------> n_d
n_a --PREREQUISITE-> n_e --PREREQUISITE--> n_c
```

```
$ node apps/api/test/integration/downstream-equivalence.test.ts
✔ 同一张图：纯函数与 SQL 的下游结果 deepEqual（P1-1）
✔ SQL 只走 DERIVED_FROM：把 CITES 起点单独跑一遍必须是空集
```

四个起点逐一比对（SQL 结果 vs 纯函数结果，排序后 `deepEqual`）：

单测同步更新，新增三条与新语义直接相关的断言：


## 5. §4 顺带修的三项

### P2-4 `CycleError.cycle` 现在是真实环路径

`topoSort` 失败时用 DFS 回溯找环（`findCycle()`），返回首尾相同的路径，例如 `A → B → A`。
新增断言：`A→B→A` 与 `B→C` 并存时，`cycle.length === 3`、首尾相同、集合为 `{A,B}`、**不含 C**。

```
✔ 有环时 topoSort 抛 CycleError，cycle 是真实环路径 A→B→C→A
✔ P2-4：cycle 不含不在环上的节点（A→B→A 与 B→C 并存）
```

### P2-5 CTE 不再静默截断

`downstream.sql` 输出改为三列：`nodeId` / `depth` / `truncated`。
`truncated = bool_or(depth >= 64)`，意味着"这个节点处在被上限截断的位置，还有更深的下游没展开"。
文件头写明了调用方必须检查该标志。

### P3-1 迁移脚本改名

```json
"db:deploy":     "migrate deploy",   // 日常应用迁移
"db:migrate:dev": "migrate dev",     // 只在改 schema 时用
```

原来的 `db:migrate`（指向 `migrate dev`）已移除，避免误触发 reset。
