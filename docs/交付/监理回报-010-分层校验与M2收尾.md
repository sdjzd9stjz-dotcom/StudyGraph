## 1 · 分类器

`apps/api/src/spans/claim-support.ts`：

```ts
export type ClaimVerdict = 'VERIFIED' | 'PENDING_REVIEW' | 'UNVERIFIED'

export function classifyClaim(input: {
  name: string; definition: string; quote?: string; spanText: string
}): { verdict: ClaimVerdict; reasons: ClaimReason[]; similarity: number; lengthRatio: number } {
  const similarity = quote ? bigramJaccard(quote, definition) : 0
  const lengthRatio = quote.length > 0 ? definition.length / quote.length : 0

  // A1：引文必须逐字出现在 span 原文里。失败就是造假，直接 T3，没有例外。
  if (quote.length === 0) return { verdict: 'UNVERIFIED', reasons: ['NO_QUOTE'], similarity, lengthRatio }
  if (!input.spanText.includes(quote)) return { verdict: 'UNVERIFIED', reasons: ['A1_QUOTE_NOT_IN_SPAN'], ... }

  // 结构条件：名称在定义里、定义含谓词（否则只是标题）
  if (!normalizedDefinition.includes(normalizedName)) reasons.push('NAME_NOT_IN_DEFINITION')
  if (!PREDICATE.test(definition)) reasons.push('NO_PREDICATE')
  if (reasons.length) return { verdict: 'UNVERIFIED', reasons, ... }

  // T1：逐字
  if (definition === quote) return { verdict: 'VERIFIED', reasons: [], ... }

  // T2：转述（bigram 相似 + 长度比）
  if (similarity < REVIEW_MIN_BIGRAM_SIMILARITY) reasons.push('BELOW_SIMILARITY')
  if (lengthRatio < REVIEW_MIN_LENGTH_RATIO || lengthRatio > REVIEW_MAX_LENGTH_RATIO) reasons.push('LENGTH_RATIO_OUT_OF_RANGE')
  return reasons.length ? { verdict: 'UNVERIFIED', ... } : { verdict: 'PENDING_REVIEW', reasons: [], ... }
}
```

- `reasons` 是**可读失败清单**：`NO_QUOTE` / `A1_QUOTE_NOT_IN_SPAN` / `NAME_NOT_IN_DEFINITION` /
  `NO_PREDICATE` / `DEFINITION_EQUALS_NAME` / `BELOW_SIMILARITY` / `LENGTH_RATIO_OUT_OF_RANGE`。
- `extract` 写状态、`card` 建卡、漂移巡检**都调这一个函数**，没有第二套判断。
- 相似度是字符 bigram Jaccard（去空白与标点），**没有模型参与**。

**单测 7 条全绿**（`apps/api/test/unit/claim-classify.test.ts`）：T1/T2 正例、A1 铁律（引文编造 → UNVERIFIED）、
无引文、标题式、长度比越界、Jaccard 自比=1。

### 5.1 A 项（006 §1.3）+ 三问

```
pageHash initial true changedQuote false
pageHash changedPage {"ok":false,"reason":"TEXT_MISMATCH","detail":"第 1 页 [0,1) 期望「a」实际「x」"} negative BAD_RANGE
missingVersion initial true changedQuote false

```

四行逐项对齐：`changedQuote=false`、`changedPage=ok:false/TEXT_MISMATCH`、`negative=BAD_RANGE`，两种模式都成立。

**三问：**

1. **第一轮怎么修的？** 把缓存键从 `(id, page, charStart, charEnd)` 改成额外带上**页文本 sha256**，
   条目里存版本号；`loadSourceVersion` 存在时用版本判定新鲜度。
2. **为什么修完仍有两条路径返回 true？** 我把"原文会不会变"当成了缓存失效的唯一原因，
   没把判定函数 `slice(...) === span.text` 的**全部输入**列出来——`span.text` 本身不在键里，
   于是换个期望文本照样命中；同时 `?? 'unknown'` 把"取不到版本"折叠成一个稳定值。当时的验收方式是
   "跑一条改页文本的用例过了"，那验证的是症状，不是不变量。
3. **这轮怎么防止同类问题？** 加了**缓存路径 ≡ 无缓存路径**的随机等价性测试
   （`span-cache-equivalence.test.ts`，200 组随机输入，含改期望文本、改页文本、版本取不到）：
   缓存键只要漏掉判定函数的任一输入，某组随机输入就会让两条路径分叉，测试必红。
   写它的过程中它当场抓到一次"测试桩谎报版本"，说明这条防线是有效的。
