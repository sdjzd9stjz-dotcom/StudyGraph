## 1. 项目是什么（给完全没上下文的人）

面向大学生的**节点式 AI 学习工作流平台**，打包成 Windows 桌面应用（Electron + 内置 PostgreSQL）。

学生在画布上把课件变成可溯源的知识卡、方法卡、题目，用连线串成学习路径。

- **技术栈**：Next.js 14 App Router（`output: 'standalone'`）+ Fastify + Prisma 6 + PostgreSQL 16 + pgvector + Electron 33
- **画布库**：`@xyflow/react@12.12.1`（React Flow）
- **节点类型**：17 种，定义在 `packages/contracts/src/`（端口、类型校验、连线合法性都在这里）
- **五条产品硬约束**：溯源是物理约束 / 执行必须显式触发 / 写作类只给骨架 / 出题必须过三检 / 干扰项必须诊断错因

目录速览：

```
apps/web/          Next 前端（画布、题库、复习、设置）
apps/api/          Fastify 后端（节点执行器在 src/nodes/executors/）
apps/desktop/      Electron 主进程 + 内置 PostgreSQL 启动逻辑（pg.cjs）
packages/contracts/ 前后端共享的类型、端口定义、连线校验
packages/db/       Prisma schema 与迁移
scripts/           构建打包（build-desktop.mjs、desktop-installer.iss）
docs/              使用说明书、人工验收清单、各种交接
```

## 2. 这一轮（11-23~11-24）到底改了什么

### 2.1 组 = 由数据派生的画布节点

组**不是**存在 `useNodesState` 里的节点。它由 `groups` 数组派生：

```ts
// apps/web/components/canvas/CanvasWorkbench.tsx
const GROUP_ID_PREFIX = '__group__'
// groupNodes = useMemo(() => groups.map(...))
// id: `__group__${group.id}`，type: 'sgGroup'
```

**这个设计是很多坑的根源**，接手时务必记住：

- 组节点每渲染一次都是**新对象**（不是稳定引用）
- React Flow 用 `node.internals.handleBounds` 找端口；对象重建后量测可能作废
- 派生节点不会进 `useNodesState`，所以它的 `measured` 必须手工写回 `groups`，
  否则 React Flow 判定"没测量完" → `visibility: hidden`（这正是 11-23 那个
  "点打包什么也没发生"的真因，见提交 `f22fdd9`）

两种形态（用户明确要求的视觉）：

| 形态 | 表现 |
| --- | --- |
| 展开 | 彩色**虚线框**，左上角写名字 + 开合按钮 + ⋯ 菜单；右侧出点、左侧入点 |
| 收起 | 成员朝框的**左上角**叠成一摞（约 220ms），全部叠好后才出现带阴影的折叠卡片 |

锚点约定：`posX/posY` 是**折叠卡片所在的绝对位置**，也是展开后虚线框的左上角。

## 3. 那些"必须知道否则会重踩"的真因

这些都是**实际踩过、排查了很久**的问题，不要重新发明：

### 3.1 React Flow 把节点设成 `visibility: hidden`

```
React Flow 渲染节点时：measured.width ? 'visible' : 'hidden'
measured 要等 ResizeObserver 回填
组节点是派生对象，如果测量结果没写回 groups，下次渲染又变回"没测量"
→ 永远 hidden，看起来就是"点打包什么也没发生"
```

**修法**：给派生节点显式 `width`/`height`，并把 `dimensions` 变化写回 `groups`（见 `onNodesChange` 包装）。

### 3.2 `pointerEvents: 'none'` 与端口

组的展开态外层必须 `pointerEvents: 'none'` —— 否则它盖在成员节点上方，
把成员的点击/框选/拖拽全吃掉（这是"框里节点点不动"的原因）。

端口和左上角标题条各自写 `pointerEvents: 'auto'`，按 CSS 规范子元素能在 `none` 的父元素里恢复命中。
**但这条在真实画布上是否成立，正是 §4 待查的问题之一。**

### 3.3 严格模式：源只能接目标

React Flow 默认 `connectionMode: 'strict'`——`source` 端口只能落到 `target` 端口。
组之前**只有出点、没有入点**，所以从普通节点拖过来永远吸附不上。
这就是"反向连线无法连接"的真因，已由 `group-in` 修复。

### 3.4 多选覆盖层吃掉右键

`.react-flow__nodesselection` 是 `pointer-events: all` 的覆盖层，
框选多个节点后右键，`onNodeContextMenu` 和 `onPaneContextMenu` **都不会触发**。
必须用 `onSelectionContextMenu`。

### 3.5 `window.prompt` 在 Electron 里不可用

它返回 `null` 且不报错。所以重命名、起名、拒绝理由全部改用应用内对话框
`apps/web/components/ui/PromptDialog.tsx`（`usePrompt()` 提供 `prompt/confirm`）。
**任何人再写 `window.prompt` 都会静默失效。**

### 3.6 其他

- 库在 click 之前就会改选中态 → Shift 增选要用 `pointerdown` 时的快照（`apps/web/lib/selection.ts`）
- 库的 `multiSelectionKeyCode` 在 Electron 里不可靠 → 设成 `null`，自己接管
- `@keyframes` 不能内联在 style 对象里，必须写进 `globals.css`（已有 `sg-spin`）

## 4. 🔴 未解决问题：组右侧出点「按得下去、拉不出线」

**这是当前最需要被解决的事。**用户报过三次，前两次的"修复"都没解决。

### 4.1 现象

- 从组的 `group-out` 按下拖动，画布上**不出现跟随鼠标的连线**
- 松手到合法目标上通常什么也不发生
- **刚进画布、还没做任何操作时有时能拖一次**，之后再也拖不出来
- 从普通节点的输出口往外拖**一直正常**

### 4.2 已经核实的事实（别重复验证）

1. 端口 DOM 存在且可点：
   - `data-nodeid="__group__g1"`、`data-handleid="group-out"`
   - class 含 `source connectable connectablestart connectionindicator`
   - `getComputedStyle(...).pointerEvents === 'auto'`
   - `document.elementFromPoint(端口中心)` 命中的就是端口本身
2. 在**某一个版本的复现页**里，合成 `mousedown` + `document` 上的多次 `mousemove`
   **确实触发了 `onConnectStart` 和 `onConnect`**，拿到
   `{source: '__group__g1', sourceHandle: 'group-out', target: 'target-1'}`。
   说明 `onConnect` 的分支判断本身是通的。
3. 但复现页改动之后同样的合成事件再也不触发（连普通节点都不行）——
   原因是复现页自己 hydration mismatch（首帧读了 `window.location`），整棵树被重挂。
   **复现页的证据因此不可信，别拿它当结论。**（复现页已删除）
4. React Flow 只用 `node.internals.handleBounds[type]` 找起始端口
   （`node_modules/@xyflow/system/dist/esm/index.mjs` 的 `getHandle()` / `XYHandle.onPointerDown()`）。
   `handleBounds` 为 `undefined` 时**直接 return，不报错、不画线** —— 表现正好是"按下去什么也没有"。
   `handleBounds` 由 ResizeObserver → `updateNodeInternals()` 填充。

### 4.3 当前的假设与已做的修法（未验证）

假设：`onConnectStart` 里 `setConnectDraft(...)` 让 `groupNodes` 的 memo 重算，
**按下出点的那一刻所有组节点对象被重建**，React Flow 重新 adopt 时 `handleBounds` 作废；
拖动过程中尺寸没变、ResizeObserver 不会再回调 → 端口位置拿不到 → 拉不出线。
"刚进画布能拖一次"也符合这个解释。

已做的改动（提交 `fd223eb`）：

- 新增 `apps/web/components/canvas/connect-draft.tsx`：高亮改由 React **context** 下发
- `groupNodes` 的依赖**去掉** `connectDraft`
- `<ReactFlow>` 外包 `ConnectDraftContext.Provider`
- `SgGroupNode` 优先从 context 读高亮
- 新增 `useEffect`：`groupNodes` 变化后 `requestAnimationFrame` 里调 `updateNodeInternals`

**接手后的第一步验证**：在真实画布（不是合成事件）里从出点拖一次。
如果仍然不行，看 `提示词-组出点连线排查.md`（根目录），那份是写给另一个 AI 的完整排查包。

### 4.4 建议的下一步思路

1. 先解决"跑不起画布"（§7.1），否则一切靠猜
2. 若假设成立 → 确认 context 方案生效即可
3. 若不成立 → 重点查：
   - React Flow 对"每帧重建的节点对象"如何缓存 `handleBounds`
   - 祖先 `pointer-events: none` 对 **mousemove 期间的事件目标**有无影响
     （`elementFromPoint` 只代表静态命中测试，不代表拖动中的事件流）
   - 组节点叠在成员上方时，`elevateNodesOnSelect` 是否让某个成员盖住了端口

## 10. 一句话记住的教训

**这个项目里的"看起来该通"不等于"通"。** 组的每个问题（不可见、拖不动、连不上、
位置丢失）都不是逻辑写错了，而是**和 React Flow 内部的量测/事件机制冲突**。
遇到画布问题时，先看库源码里对应的 selector 和事件路径，别在业务代码里加补丁。
