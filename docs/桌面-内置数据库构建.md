# 桌面版内置 PostgreSQL：构建与验收

> 对应交接文档 §5.2① 。目标是让桌面客户端不再依赖 Docker —— 学生机器上没有 Docker，也不该有。
>
> 本文只写**已经跑通并留下终端原文**的步骤。没跑通的写在最后一节「已知限制」。

---

## 0. 一句话结论

官方 Windows 二进制里没有 pgvector，必须自己编译。
而 **PostgreSQL 的二进制和它的数据目录都不能放在含中文的路径下** ——
这一条决定了整个运行时必须是「安装时带一份、首次启动释放到 ASCII 路径」，不能就地运行。

---

## 1. 为什么必须自编译 pgvector

迁移第一份文件第 8 行就是：

```sql
CREATE EXTENSION IF NOT EXISTS "vector";
```

`Concept.embedding` 是 `vector(1536)`。没有 pgvector，建表链在第一份迁移就断，
后面 6 份全部级联失败。实测报错（缺 pgvector 时）：

```
psql:.../20261118030000_init/migration.sql:8: ERROR:  extension "vector" is not available
DETAIL:  Could not open extension control file ".../share/extension/vector.control": No such file or directory
```

官方 EDB 的 Windows 二进制包**不含** pgvector，所以只能在本机用 PG 自己的头文件编译。

## 2. 准备运行时（一次性）

### 2.1 下载官方 PostgreSQL 16 二进制

```powershell
mkdir C:\tmp\pgstage
curl.exe -L -o C:\tmp\pgstage\pg16.zip https://get.enterprisedb.com/postgresql/postgresql-16.9-1-windows-x64-binaries.zip
tar -xf C:\tmp\pgstage\pg16.zip -C C:\tmp\pgstage
```

解压后是 `C:\tmp\pgstage\pgsql`（约 836MB，其中 pgAdmin 4 占 692MB，打包时会剔掉）。

### 2.2 编译 pgvector

```powershell
curl.exe -L -o C:\tmp\pgstage\pgvector.zip https://github.com/pgvector/pgvector/archive/refs/tags/v0.8.0.zip
tar -xf C:\tmp\pgstage\pgvector.zip -C C:\tmp\pgstage
```

构建脚本（`C:\tmp\pgbuild\build-pgvector.bat`）。**三个环境变量缺一不可**，都是踩出来的：

```bat
@echo off
rem 必须用 14.44 工具链：14.51 只装了 OneCore CRT，没有桌面版 libcmt.lib，链接必然 LNK1104
set "VC=C:\Program Files\Microsoft Visual Studio\18\Community\VC\Tools\MSVC\14.44.35207"
set "SDK=C:\Program Files (x86)\Windows Kits\10"
set "SDKV=10.0.26100.0"
set "PGROOT=C:\tmp\pgstage\pgsql"
set "PATH=%VC%\bin\Hostx64\x64;%PGROOT%\bin;C:\Windows\System32"
set "INCLUDE=%VC%\include;%SDK%\Include\%SDKV%\ucrt;%SDK%\Include\%SDKV%\um;%SDK%\Include\%SDKV%\shared;%SDK%\Include\%SDKV%\winrt"
set "LIB=%VC%\lib\x64;%SDK%\Lib\%SDKV%\ucrt\x64;%SDK%\Lib\%SDKV%\um\x64"
cd /d C:\tmp\pgstage\pgvector-0.8.0
nmake /F Makefile.win
nmake /F Makefile.win install
exit /b %errorlevel%
```

三个必须点：

| 变量 | 缺了会怎样 |
| --- | --- |
| `PGROOT` | `Makefile.win(24) : fatal error U1050: PGROOT is not set` |
| `LIB`（指向 14.44 + SDK） | `LINK : fatal error LNK1104: 无法打开文件"LIBCMT.lib"` |
| `PATH` 里带 `%PGROOT%\bin` | 链接阶段找不到 `postgres.lib` |

`nmake install` 会把 `vector.dll` 放进 `pgsql/lib/`、`vector.control` 与
`vector--0.8.0.sql` 放进 `pgsql/share/extension/`。

### 2.3 裁出可打包的运行时

```bash
node scripts/prepare-pg-runtime.mjs
```

产出 `vendor/pg16`（**66.2 MB**，已忽略入库）。脚本做三件事：

1. 剔掉 `pgAdmin 4` / `StackBuilder` / `doc` / `include`、`bin` 里的 `wx*.dll` 与 `stackbuilder.exe`、`lib` 里的 `.lib`/`.exp`、`share/locale`
2. **逐项校验**必需文件，缺 pgvector 直接失败并说明原因（不做「缺了也能过」的降级）
3. 写 `PG-BUNDLE.json`：版本 + `postgres.exe` / `psql.exe` / `vector.control` / `vector.dll` 的 sha256

## 3. 中文路径：这一节是整件事的核心

PostgreSQL 在 Windows 上对非 ASCII 路径的失败方式**完全不相干**，会把人带偏：

| 哪个东西在中文路径下 | 实际报错 |
| --- | --- |
| 二进制 | `initdb: error: could not create directory "...": Permission denied` |
| 数据目录 | `initdb: FATAL: invalid byte sequence for encoding "UTF8": 0xb8` |

判据（实测）：两份 `initdb.exe` 的 sha256 **完全相同**，放在 `C:\tmp` 下就能跑通，
放在 `D:\ai学习辅助工作流搭建\vendor\pg16` 下就报 Permission denied。
所以这是路径问题，不是文件损坏、不是杀软、不是权限。

### 3.1 因此的设计

- 运行时与数据目录都解析到**纯 ASCII** 位置
- 候选链（中文 Windows 的用户名常是中文，`%LOCALAPPDATA%` 自身就可能非 ASCII）：
  1. `%LOCALAPPDATA%\StudyGraph`
  2. `%ProgramData%\StudyGraph`
  3. `%SystemDrive%\StudyGraph`
- 安装目录本身是 ASCII 时**就地使用**运行时（省一次 66MB 复制）；否则首次启动释放到上述位置
- 显式覆盖：环境变量 `STUDYGRAPH_DATA_DIR`（也必须是 ASCII，否则直接报错说明原因）

释放的幂等性靠 `.bundle-key` 文件：内容为 `PostgreSQL 版本 | vector.dll 哈希前 16 位`。
内置运行时换版本时键会变，自动重新释放，不会新旧 dll 混用。

## 4. 迁移执行

不调 `prisma migrate deploy`（打包产物里不带 Prisma CLI），而是自己按 psql 跑，
**账目格式照抄 Prisma 的 `_prisma_migrations`** —— 这样以后用 Prisma 接管这个库时，
它认为这些迁移已应用，不会重复建表。

每条迁移：

1. `sha256(migration.sql 原始字节)` 作为 checksum
2. 已登记且 checksum 不同 → **报错并停止**（改动已应用的迁移是新旧库分叉的源头）
3. 先插入登记行（`started_at`），再 `psql -f` 执行
4. 执行失败 → 删除登记行 → 报错（否则下次启动会以为它已应用，留下半截库）
5. 成功 → `UPDATE ... SET finished_at = now(), applied_steps_count = 1`

### 每条断言删掉会漏什么

| 断言 | 删掉会漏的 bug |
| --- | --- |
| 首次启动从空目录跑通 | 只在用户第一次双击时暴露 |
| 结构指纹 8 项 | 「迁移通过」但对象没建全，接口运行时才炸 |
| 第二次启动不重跑 | 用户第二次打开软件，`CREATE TABLE` 重放直接崩 |
| 篡改迁移被拒 | 新旧库结构悄悄分叉，没人发现 |
| 迁移失败要停库 | 残留 postgres 占住数据目录，下次报「Permission denied」这种假线索 |

## 6. 踩过的坑（都在代码里留了注释）

| 坑 | 表现 | 修法 |
| --- | --- | --- |
| `pg_ctl start` 管道继承 | 数据库起来了，但 `spawnSync` 永远不返回（postgres 继承了 stdout 管道） | 启动那步 `stdio: 'ignore'`，失败信息读 `-l` 日志 |
| 迁移失败留下孤儿实例 | 数据目录被锁死，连删除都 EPERM | try/catch 里先 `pg_ctl stop` 再抛 |
| 顶层文件漏复制 | 裁剪脚本只复制目录，`PG_VERSION` 之类顶层文件丢了 | 顶层普通文件一并复制 |
| 用 `PG_VERSION` 取版本 | 二进制包没有这个文件（那是 initdb 写的） | 改从 `pg_config --version` 读 |
| 双实例 | 第二个实例会把第一个正在用的库停掉 | `app.requestSingleInstanceLock()` |
| 127.0.0.1 开 trust | 本机任意进程都能读学习数据 | initdb 时随机生成密码，`scram-sha-256` |

## 7. 已知限制（尚未做）

- **首次启动没有自建本地身份 —— 这是当前最挡路的一条。**
  接口用 PAT 鉴权（`Authorization: Bearer sg_pat_...`），而空的内置库里没有任何用户和 token，
  所以 `/v1/canvases` 一律 401；前端「新建画布」读 `NEXT_PUBLIC_DEV_PAT`，打包后是空串，
  点下去同样 401。开发期一直靠仓库 `.env` 里的 dev token 顶着，桌面版必须自己解决。
  最小做法：首次启动时在主进程里建一个本地用户 + 全 scope 的 PAT
  （`sha256` 存库，明文只放进程环境变量 `STUDYGRAPH_DEV_PAT` 传给 Web/API），
  这一步做完，桌面版才算真正可用。
- **安装包**：目前仍是目录形态 + 手工复制。`.exe` 安装器（Inno Setup / NSIS）未做。
- **卸载选项**：保留 / 删除数据的选择未做。数据在 `%LOCALAPPDATA%\StudyGraph\pgdata`。
- **PG 大版本升级**：需要 `pg_upgrade` 或导出重导，未实现。当前只保证同一 16.x 内升级安全。
- **对象存储仍未本地化**：S3 还依赖 Docker 的 SeaweedFS，见交接文档 §5.2③。
