### 3.2 LLM Gateway（`apps/api/src/llm/`）

**接口按规格原文实现，字段名不许改：**

```ts
interface LLMGateway {
  complete(req: {
    taskType: 'chunk' | 'extract' | 'quiz' | 'probe' | 'method' | 'solve' | 'variant' | 'check' | 'judge'
    messages: Message[]
    jsonSchema?: JSONSchema
    cachePrefixKey?: string
    user: UserCtx
  }): Promise<{ data: unknown; usage: TokenUsage }>
}
```

**要求：**

- 首期两个 provider：`providers/openai.ts`、`providers/anthropic.ts`，**同一接口**
- `routing.ts`：`taskType → 模型`。规格明文要求切片/抽取/判分路由到**小模型**，`probe`/`method`/`solve`/`variant` 路由到**前沿模型**。这条要有表，不能散在 if 里
- **前端绝不直连厂商**（M1 已验证零命中，M2 不许破例）
- `TokenUsage` 必须是**厂商返回的真实值**，不是估算。缓存命中时 `tokensIn = tokensOut = 0`
- 前缀缓存键按 `(sourceId, 章节范围, promptVersion)` 组织（规格 §5.2）
- **失败必须抛出，不许返回空对象让上层当成功**

**BYOK：** 从 `ProviderCredential` 解密（AES-256-GCM，主密钥来自 `BYOK_ENCRYPTION_KEY`，绝不落库）。M2 至少要把解密路径跑通一次——**但这依赖 §0.1 的凭据。**

### 3.3 Executor 契约与 registry

**按规格原文，字段名不许改：**

```ts
export interface NodeExecutor<P = any> {
  type: string

  outputs: JSONSchema
  run(ctx: {
    params: P
```

**registry 启动自检（这条是防半实现上线的关键）：**

- 启动时检查 `NodeType` 的 17 个值是否都有 executor

- 标记方式：`registry.ts` 里一份 `IMPLEMENTED: NodeType[]` 与 `PLANNED: NodeType[]`，两者并集必须等于 17
- **未实现的节点被调用时返回 501 `EXECUTOR_NOT_IMPLEMENTED`**，不许静默返回空对象

**证明：** `registry` 自检的输出，以及调用未实现节点的 501。

### 3.5 `source`：解析与 span 索引

**这是整个溯源链的地基，做歪了后面全歪。**

**必须明确的定义（现在就要定，不许含糊）：**

`Span.charStart` / `charEnd` 的偏移**相对于什么文本**？三选一，选定后写进 `docs/architecture.md` 并在代码注释里重复一遍：

- (a) 该页的纯文本（推荐）
- (b) 整个文档的纯文本
- (c) 某个规范化后的字符串

**这个定义必须能让第三方复现。** 我会用你的验证脚本重新解析同一个 PDF，比对 `Span.text` 与 `pageText.slice(charStart, charEnd)` 是否逐字符相等。

**要求：**

- 存原文到 S3：`canvas/<canvasId>/source/<sourceId>/original.pdf`
- 大产物（原文、span 索引）走 S3，`Artifact.structured` 只留摘要
- `Source.checksum` 存文件 sha256
- `Source.pageCount` 存真实页数（**不许填死值**）
- `Source.parsedAt` 在成功解析后写入

**扫描版 PDF（无文字层）：**

- 必须**解析失败**，或产出 `UNVERIFIED`
- **绝不能凭空生成内容**
- 错误信息要能让学生看懂："这份 PDF 没有文字层，可能是扫描件，M2 暂不支持 OCR"

### 3.6 `extract`：概念抽取

- 输出 `name` / `definition` / `spanIds[]`
- **每条 claim 必须有至少一个 `spanId`**，没有就标 `UNVERIFIED`
- 走小模型（`taskType: 'extract'`）
- 用 `jsonSchema` 强制结构化输出，不许靠正则解析模型自由文本

### 3.7 `card`：概念卡

**硬约束 1 的落点，本项目最重要的一条。**

- 输入是 `extract` 的 claims，**不许从零生成正文**
- 每条入卡论断必须有可 resolve 的 span
- span 不存在 / 原文校验和不符 → `UNVERIFIED`，**不得进入 `ConceptCard`**
- 写 `Concept` 时先建 `UNVERIFIED`，写 `ConceptCitation`，再置 `VERIFIED`
  （数据库触发器会拦住顺序错误，M1 已实测）
- 产出 `Artifact(kind=CONCEPT_CARD)`

### 3.8 指纹与缓存

**算法（规格原文）：**

```
fingerprint = sha256(
  canonicalJson(上游 artifacts 的 hash 列表)
  + canonicalJson(node.params)
  + modelVersion
  + promptVersion
)
```

**这里有一个我要特别指定的点：**

> **`promptVersion` 必须是 prompt 模板文本的哈希，不是手写常量。**

理由：手写常量（`const PROMPT_VERSION = 'v1'`）意味着"改了 prompt 忘了改常量"就会命中旧缓存，而没人会发现。用 `sha256(promptText).slice(0, 12)` 则改一个字就自动失效。

同样，`modelVersion` 必须取自**实际调用的模型标识**（如 `gpt-4o-mini-2024-07-18`），不是你在配置里写的别名。

**行为要求：**

| 场景 | 要求 |
| --- | --- |
| 首次运行 | 正常调模型，`tokensIn/Out` 为真实值，`cacheHit=false` |
| 同参数二次运行 | `tokensIn=0`、`tokensOut=0`、`cacheHit=true`，**不调模型** |
| 改 params 再运行 | 指纹变，缓存未命中，**正常消耗 token** |
| 改 prompt 文本再运行 | 指纹变，**必须未命中** |
| 改 modelVersion 再运行 | 指纹变，**必须未命中** |
| 上游 artifacts 变 | 指纹变，未命中 |

### 3.9 显式触发与 stale

**硬约束 2，M1 已验证 `mark-stale` 不入队。M2 要保持：**

- 上游完成后 → 下游只置 `STALE`，**不自动跑**
- 用户点执行 → 先返回 `estimatedTokensIn/Out`（由上次同类 run 的用量 + 本次输入规模估算）
- 用户确认后才入队
- `Run.trigger` 记录来源（`user` / `mcp` / `retry`）

**`gate` 节点的 `AWAITING_APPROVAL` 状态 M2 不用实现**（那是 M5 的事），但 `POST /v1/nodes/:id/run` 必须支持"预览估算"与"确认执行"两步——**规格明文要求"重跑前展示预计 token 消耗"**。

建议接口（形状你定，但两步必须分开）：

```
POST /v1/nodes/:id/run?dryRun=true   → { estimatedTokensIn, estimatedTokensOut, cacheHit }
POST /v1/nodes/:id/run                → { runId }
```

### 3.10 BullMQ 与执行流

- 一个队列，`node.run` job
- worker 与 API 同进程（M2 不拆服务），但代码分层要能拆
- `Run.status` 走 `QUEUED → RUNNING → SUCCEEDED|FAILED`
- 失败要写 `errorCode` / `errorMessage`，**不许只打日志**
- 幂等：同一 fingerprint 的 job 重复入队，不能产生两条成功 Run

### 3.11 span 溯源抽屉（前端）

- 概念卡上的引用角标可点
- 点开右侧抽屉，显示原文并**高亮 span**
- 高亮范围必须与 `charStart/charEnd` 一致
- PDF 页码要能定位到正确页

**M2 的最低要求：** 抽屉能打开、能显示正确原文片段、高亮范围正确。**PDF 内嵌渲染可以延后**（先渲染该页纯文本 + 高亮，M4 再做 PDF.js 画布）。

### 3.12 不做的事

- 不做 `prereq` / `quiz` / `grade` / `review`（M3）
- 不做 knowledge / method 视图（M3 / M5）
- 不做 MCP / SSE（M4）——**但 `Run` 表与状态机现在就要对**
- 不做 OCR
