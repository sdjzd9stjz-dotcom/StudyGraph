## 1. 【P0】`source` 的指纹不含文件内容

### 1.1 证据

E7 的构造方式：把 `课件/[0]` 拷到临时路径 → 跑 → **SUCCEEDED**；然后把 `课件/[1]` 覆盖到同一个临时路径 → 再跑：

```
first SUCCEEDED
replacement CACHED        ← 文件内容已经换了，仍然命中缓存
```

**同一个 `params.localPath`、不同的文件内容，指纹没有变。**

### 1.2 为什么是 P0

这与 A 项是**同一个错误在前一个环节的重演**：

| | 用作判定身份的东西 | 真正决定结果的东西 |
| --- | --- | --- |
| **A 项** | span 的 `(id, page, 区间)` | `span.text` + 页文本 |
| **本项** | `params.localPath` | **文件字节内容** |

后果很具体：学生在画布上把传错的文件换掉、重跑，系统返回上一次的结果，**并且显示"已完成"**。他以为处理的是新课件，实际看到的是旧课件的切片和卡片。全程没有任何提示。

`source` 是整个链路的最上游。它的指纹错了，下游全部建立在错误的产物上，而且因为下游指纹正常，缓存会继续命中，错误会一路传播。

### 1.3 要求

**`source` 的指纹必须包含文件内容摘要，不能只含路径。**

- 建议直接用文件的 `sha256`（你们 `extract-text.ts` 里已经在算 `checksum`，复用它即可）
- 或者：在计算指纹之前先读文件、算摘要、把摘要并进 `params` 的规范化输入

**关键点：** 不要试图用 `mtime` / `size` 代替。`mtime` 在拷贝、解压、同步场景下不可靠——E7 的测试恰好就是"同名覆盖"，`mtime` 会变但这不是保证。

**可选但推荐：** 若读文件失败（路径不存在），直接报错，**不要退回到"只用路径"算指纹**。那等于把这条 P0 换个写法保留下来。

### 1.4 复验命令（沿用 E7，但期望值改变）

```powershell
# 用同一份 E7 脚本，第三行输出必须是 SUCCEEDED 而不是 CACHED
first SUCCEEDED
replacement SUCCEEDED        ← 必须
```

**并且追加一条更强的**：换文件后，两次产出的 `Span` 数量或文本必须不同。

```powershell
# 建议这样验：跑完 replacement 之后查该 Source 的 span 总数
# 必须等于【第二个文件】的 span 数，不是第一个文件的
```

### 1.5 顺带说明

E6 的 `NEGATIVE {..., "sources":0, ...}` 之后，E7 里 `negativeSources 1`。

两个数不一样，是因为**用的不是同一份 PDF**（E6 用 `高代.pdf`，E7 用 `数学分析`）。这个差异本身不是缺陷，但报告 §4 写了一句"**Source 行只在抽到文字后创建**"，被这两组证据同时否定了一半。**下一轮的文档里，这类概括句请加限定条件**（"对 0 字符的文件"）。

## 2. 【P1】垃圾文字层通过了闸门 —— 这是本轮最值得注意的发现

### 2.1 证据

E10 把 `、理科数学分析（上册）...pdf` 的 span 列了出来：

```
261 页 → 30 个 span
13 页 ：「⾃ 整 有理实」
17 页 ：「XEX 唯⼀yEY」
40 页 ：「i」
47 页 ：「苦 tO'P 1时⼀⼀an Hit it 六71⼗ it it ⼥ ⼥⼗平 ⼗合 ⼀⼆1⼗1⼗ 1t.i.tl」
163 页：「féiidx⼆fed et州品贸品然品poTikxi cl u l」
172 页：「f x 4inx 1 dX19sint dtloXhintdtFc sinx2」
```

**这不是没文字层，是有文字层但内容不可用。** 典型的劣质 OCR（扫描书被粗暴识别过一遍），字符能读出来，但不是人话。

### 2.2 为什么这个比 `高代.pdf` 更危险

`高代.pdf` 是 0 字符 → 被拒 → 安全。
`数学分析` 是 30 页有零星字符 → **被接受** → 30 个 span 落库 → 下游 `chunk` 切出 30 个 chunk → `extract` 面对「苦 tO'P 1时⼀⼀an Hit it」去抽概念。

模型会怎么做？两种可能，**都糟**：

1. 抽不出来 → 返回空 claims → 用户以为"这本书没内容"
2. **抽出来了** → 编出听着像那么回事的概念定义，然后挂一个"可 resolve 的 span"指向 `47 页 [0,55)`

第二种是灾难：**span 校验会通过**（因为 `Span.text` 确实等于那串乱码），`ConceptCitation` 成立，`Concept.status` 变成 `VERIFIED`，数据库触发器也不拦。

> **约束 1 的整条防线，在这份文件面前是失效的。**
> 它拦得住"没有引用"，拦不住"引用了一段谁也没法验证的乱码"。

### 2.3 要求

**必须加一道「文字层可用性」闸门，与「有没有文字」分开。**

当前的判定是"有文字就算成功"。改成两层：

| 层 | 判定 | 失败时的行为 |
| --- | --- | --- |
| 第一层 · 有无 | 全文 0 字符 | `422 SOURCE_HAS_NO_TEXT_LAYER`（现有，保留） |
| **第二层 · 可用** | **有字符，但不构成可用文本** | **`422 SOURCE_TEXT_LAYER_UNUSABLE`（新增）** |

**第二层的判定必须是可量化的，不能靠感觉。** 我把标准定在这里，机制由你选：

#### 标准 A · 有效页占比（必做）

一个"有效页"指：该页字符数 ≥ 阈值（建议 **20 字符**），且通过了标准 B 的乱码检测。

```
有效页数 / 总页数 < 阈值（建议 20%）→ 判定不可用
```

**用两份现有材料校准这个阈值：**

| 文件 | 总页 | 有字符页 | 占比 | 应当判定 |
| --- | --- | --- | --- | --- |
| `高代.pdf` | 380 | 0 | 0% | 不可用 |
| `数学分析` | 261 | 30 | **11.5%** | **不可用** |
| `ch3-4.pptx` | 32 | 18 | **56%** | 可用 |
| `ch3-1（1）.pptx` | 9 | 9 | **100%** | 可用 |

**注意 `ch3-4` 是 18/32 = 56%，14 个空页是纯图页——这是合法的稀疏，不能误杀。** 20% 的阈值能同时容纳这两种情况。

#### 标准 B · 乱码特征（必做，至少两条）

从 E10 的样本里能直接读出三个特征：

1. **康熙部首 / 兼容汉字占比**：`⼀ ⼆ ⼥ ⼗ ⽉ ⾃` 这些是 U+2F00–U+2FDF 区的字符，正常中文文本几乎不会用。**占比超过 1% 即判定异常。**
2. **拉丁字母与汉字的无意义混排**：`féiidx⼆fed et州品贸品然品poTikxi`。可用"连续拉丁字母串中不含元音结构"或"单词不在任何词典"来判，机制自定。
3. **单字符页占比**：`i`、`n`、`0`、`⼀` 这种 1 字符页，在多页材料里几乎一定是抽取失败。

**三条里至少实现两条，且每条都要有单测。**

#### 必须有可配置性

阈值写进配置（`packages/contracts/src/thresholds.ts`），**不要散在代码里**。以后遇到排版特殊的材料要能调。

### 2.4 判定结果的落点

被判定为"不可用"的 `source`：

- **不建 `Source` 行**（与"无文字层"一致）
- 不建 `Span`
- `Run.status = FAILED`，`errorCode = SOURCE_TEXT_LAYER_UNUSABLE`
- 用户可见文案要说明**为什么**，而不只是"失败了"：

```
这份 PDF 的文字层不可用（261 页中只有 30 页能识别出零星字符，
且内容多为乱码）。这通常是扫描件经过劣质 OCR 的结果。
可以换一份电子版课件，或等后续版本支持重新 OCR。
```

### 2.5 复验

```bash
# 两份扫描件必须都被拒，但错误码可以不同
# 高代.pdf         → SOURCE_HAS_NO_TEXT_LAYER
# 数学分析.pdf     → SOURCE_TEXT_LAYER_UNUSABLE
# 10 份 PPTX       → 全部 SUCCEEDED（不能误杀）
```

**这三组结果要一起贴。** 只贴"扫描件被拒"不够——必须证明**没有误杀正常的课件**，否则这个闸门就是拿可用性换安全。

## 3. 【P1】`chunk` 静默截断丢字符

### 3.1 证据

E4：

```
source=ABCDE chunk=AB
```

`params.maxChars = 2`，输入 5 个字符，输出只有一个 chunk、内容是 `AB`。**`CDE` 三个字符消失了，没有任何报错、没有任何标记。**

### 3.2 为什么不能这样

`chunk` 的下游是 `extract`。丢掉的字符永远不会被抽成概念，而**没有任何地方会显示"这里少了一段"**。

这属于作弊库第 7 条「静默降级」，而且是最隐蔽的一种：切片数量看起来正常（9 页 9 片），只有内容被悄悄截短。

### 3.3 要求

**二选一：**

**方案 A（推荐）· 切分而非截断**

`maxChars` 是"单个 chunk 的上限"，不是"整页的上限"。超长页应当切成多个 chunk：

```
ABCDE, maxChars=2 → [AB, CD, E]
```

**方案 B · 明确报错**

若认为"一页一片"是硬约束（报告 §5 提到当前设计就是这样），那 `maxChars` 就是一个危险的参数——它会让内容被砍。此时应当：

- 要么删掉 `maxChars` 参数
- 要么在 `maxChars < 页字符数` 时**抛错**，而不是悄悄截断

**无论选哪个，都必须满足：所有 chunk 的 text 拼接后，等于该页 span 的完整 text（或明确报错）。**

### 3.4 复验

```bash
# 方案 A：拼接后必须等于原文
source=ABCDE chunk=ABCDE

# 方案 B：必须抛错
# chunk 执行失败，errorCode = CHUNK_MAX_CHARS_EXCEEDS_PAGE
```

**并且要加一条针对真实材料的检查**：266 页跑完后，`SUM(length(chunk.text))` 必须等于 `SUM(length(span.text))`。

```sql
-- 这两个数必须相等
SELECT sum(length(text)) FROM "Span" WHERE region='SLIDE';
SELECT sum(length((c)->>'text')) FROM ... chunk artifacts ...;
```
