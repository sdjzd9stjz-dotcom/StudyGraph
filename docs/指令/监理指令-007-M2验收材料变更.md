# 监理指令 007 · M2 验收材料变更（PPTX 课件）

> **文号**：SG-SUP-007
> **日期**：2026-11-19
> **依据**：**用户明确授权**（"允许用课件"），答复 SG-SUP-006 §4.3 第 2 项
> **性质**：**规格偏离批准。** 本条只改 M2 的验收**材料**，不改任何硬约束与判定逻辑。
> **生效范围**：M2 主体验收；不影响 M1 已关闭结论

---

## 0. 记录这次偏离，以及它的边界

**用户批准：** M2 可以用 `课件/` 目录下的 PPTX 作为主验收材料，不必提供 60 页 PDF。

**我作为监理在这里记一笔，理由要说清楚：**

规格原文写的是「上传 60 页 PDF，5 分钟内产出 ≥15 张概念卡」。改成 PPTX 不是形式上的等价替换——**PPT 和教材是两种不同的材料**：

| 维度 | 60 页教材 PDF | 266 张 PPT 课件 |
| --- | --- | --- |
| 文字密度 | 每页 400–800 字，连续论述 | **每页平均约 22 字**（5842 字符 ÷ 266 页），以短句、标签为主 |
| 概念完整性 | 有定义、推导、例题 | 常有跳跃，依赖讲授 |
| 图文比例 | 少量插图 | 大量图表，部分页几乎无文字 |
| 页码语义 | 页 = 页 | 页 = 幻灯片序号 |

**这个差异会直接冲击验收：** 266 张幻灯片只有 5842 字符，可能**不足以稳定产出 15 张有质量的概念卡**。

**所以本轮的口径不是"换个文件继续"，而是三件事一起变：** 材料、指标、以及"材料不够时的处理方式"。

## 2. PPTX 特有的技术要求

### 2.1 文本抽取范围必须明确

一份 PPTX 里的文字可能分布在多个位置。**必须逐项决定取不取，并写进 `docs/architecture.md`：**

| 位置 | 是否抽取 | 我的要求 |
| --- | --- | --- |
| `ppt/slides/slideN.xml` 的 `<a:t>` 节点 | **必须** | 正文主体 |
| 备注页 `ppt/notesSlides/` | **必须抽取，但单独标记** | 讲稿常含关键解释，是概念卡的重要来源。**但必须在 span 上可区分**，不能和正文混为一体 |
| 表格 `ppt/slides/` 内的 `<a:tbl>` | **必须** | 表格文本同样在 `<a:t>` 里，注意不要漏 |
| 图表（chart XML）里的系列名与标签 | **建议抽取** | 抽不到不算缺陷，但要在文档里写明"未抽取" |
| 图片里的文字（截图、公式图） | **不抽取** | 不要求 OCR。**但必须导致该页文本稀疏或为空，此时不得凭空生成内容** |
| 母版 / 版式（`slideMaster`、`slideLayout`） | **不抽取** | 那是模板文字（页码、公司名），抽了会污染 |

**关键要求：** 若备注页与正文都抽取，`Span` 必须能区分来源。建议在 `Span` 上加 `region` 字段（`slide` / `notes`），或用一个稳定前缀。**M1 的 schema 里 `Span` 没有这个字段——这需要一次 migration，按规矩新开一个，不要改已应用的。**

### 2.2 `Span.page` 的语义

- PPTX：`page` = **从 1 开始的幻灯片序号**
- 与 PDF 的页码语义一致，前端无需分叉
- `charStart` / `charEnd` 的基准文本**沿用 M2 已定的定义**（页内文本，UTF-16，左闭右开）——**不许因为换成 PPTX 就改偏移基准**

**这条要特别小心**：如果 PPTX 抽取时把备注页拼进了同一页的文本，那 `charStart` 的基准就变了，所有已落库的 span 全部失效。**如果决定备注页单独成 span，就让它们各自有独立的文本基准。**

### 2.3 没有文字的幻灯片

大量 PPT 页是纯图（公式截图、示意图、表格图片）。这类页：

- 抽取结果为 0 字符
- **不得凭空生成任何内容**
- 若该页是某张卡唯一引用的页，该卡必须是 `UNVERIFIED`

**这正是 M2 最该测的场景**，而且 PPTX 天然提供了几十个真实样本，比人工构造可信。

## 4. 概念卡数量：新材料下的诚实处理

### 4.1 目标仍是 ≥15

规格的 ≥15 是基于 60 页教材设定的。**我保留这个数字作为目标**，理由是：266 张幻灯片 + 备注页讲稿，如果抽取正确，`extract` 应该能拿到足够的概念密度。

### 4.2 但如果材料真的不够

**允许下调，但有严格条件：**

1. **必须先证明材料不够**，不是先说结果不够：
   - 贴出抽取后的总字符数、去重后的有效论断数
   - 贴出 `extract` 产出的 **claims 总数**（不是卡片数）
   - 证明"claims 少"是因为材料少，不是因为抽取或提示词有问题
2. **允许的下限是 10 张**，且每张必须有真实 span 支撑
3. **绝对禁止的做法：**
   - 为了凑数把同一概念拆成多张
   - 把无 span 的内容做成卡
   - 生成通用解释（"这个概念通常指…"）而不引用课件原文

> **宁可交 10 张真卡，不要 15 张假卡。** 这条我写在这里，是因为"凑够数"是本项目最容易被诱惑的一次偷工。

### 4.3 报数方式

回报里必须区分三个数，**不许混用"概念卡"一个词**：

```
claims 产出数：__      （extract 的原始输出条数）
落库 Concept 数：__    （实际建表的条数）
其中 VERIFIED：__      （有 span 且校验通过的）
其中 UNVERIFIED：__    （被拦下的）
```

## 5. 两份扫描 PDF：转正为负例夹具

**261 页《理科数学分析》与 380 页《高代》，抽样 5 页全部 0 字符。**

这两本书**不要删，也不要 OCR**。它们是规格 §4.4 要求的真实负例素材：

```bash
# 期望行为：解析失败，或产出 UNVERIFIED，绝无任何卡片
# 且错误信息必须让学生看懂
```

**本轮必须跑这个用例，并贴出：**

| 检查点 | 期望 |
| --- | --- |
| `source` 节点状态 | `ERROR` 或 `SUCCEEDED` 但产物标记为无文字层 |
| 该 Source 下的 `Span` 数 | **0** |
| `extract` / `card` 产出 | **0 张卡** |
| 数据库检查 | `v_verified_without_citation` 仍为空 |
| 用户可见文案 | 明确说明"这份 PDF 没有文字层，可能是扫描件，当前不支持 OCR" |

**如果它产出了任何一张卡，那是 P0，比数量不够严重得多。**

## 6. 字符数口径必须对齐

两个数：工程 AI 报 **6101**，验收方实测 **5842**。

**这不是小事**——如果连"有多少字"都对不上，那 `extract` 到底处理了多少材料就说不清。

**要求：**

1. 写出精确的计数脚本（贴代码），明确：
   - 是否含 `<a:t>` 之外的元素
   - 是否含备注页
   - 是否含表格
   - 是否去重、是否去空白
2. 用同一个脚本重新计数，给出**唯一权威数字**
3. 若两个数确实对应不同口径，把两者都列出，标明各自定义

**M2 的 `Source.pageCount` 与字符统计，从此以这个脚本的输出为准。**
