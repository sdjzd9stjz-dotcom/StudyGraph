## 3. 开工前必须改（P1）

### 3.1 guards.sql 不在 migration 链路里 —— 【P1】

**实测证据：**
```
20261118030000_init/migration.sql:
  CHECK:    0
  触发器:    0
  视图:      0
```

**问题不在于内容，在于它进不了库。**

`guards.sql` 现在靠手工 psql 执行。后果：

1. 换机器 / CI / 重装系统后 `prisma migrate deploy` 起来的是**没有 CHECK、没有触发器、没有审计视图**的裸库，而且不会报错
2. `migrate dev` 的 shadow database 同样没有这些约束，后续 drift 检测以裸库为基准，漂移永远发现不了
3. 手工 psql 补跑不写 `_prisma_migrations`，下一个人不知道跑过没有

**要求：**

把 `packages/db/sql/guards.sql` 的内容原样搬成第二个 migration：

```
packages/db/prisma/migrations/20261118030100_guards/migration.sql
```

`guards.sql` 可保留作为源文件（并在文件头注明"由 migration 20261118030100 执行"），但**库里的东西必须由 migration 产生**。

**证明方式**（这四条输出我逐条比对，缺一条按未完成处理）：

```bash
docker compose up -d postgres
pnpm db:deploy

# ① CHECK 约束：应为 7
psql "$DATABASE_URL" -c "SELECT count(*) FROM pg_constraint WHERE contype='c' AND connamespace='public'::regnamespace;"

# ② 触发器：应为 3
psql "$DATABASE_URL" -c "SELECT count(*) FROM pg_trigger WHERE NOT tgisinternal;"

# ③ 视图：应为 3
psql "$DATABASE_URL" -c "SELECT count(*) FROM pg_views WHERE schemaname='public';"

# ④ 负向用例：插一条 status='VERIFIED' 且无引用的 Concept，必须报错
psql "$DATABASE_URL" -c "INSERT INTO \"Concept\" (id, \"canvasId\", name, definition, status) VALUES ('c_test','no_such_canvas','测试','测试','VERIFIED');"
```

**④ 的预期输出**必须包含 `cannot be VERIFIED without at least one source span citation`。
如果它**插入成功**了，说明触发器没生效，整条驳回，不许继续往下做。

> 注：④ 会因为 `canvasId` 外键先失败。你需要先建一个 User + Canvas，或者把这条测试改成"先建 UNVERIFIED、再 UPDATE 到 VERIFIED"。**两种都行，但必须证明触发器拦住了，而不是外键拦住了。** 报错信息里出现 `ConceptCitation` 相关字样才算通过。

### 4.1 删除引用后 VERIFIED 资产失守

**问题：** 触发器只挂在 `Concept`/`Method`/`Problem` 的 INSERT/UPDATE 上，不挂引用表的 DELETE。


**要求：** 给 `ConceptCitation` / `MethodCitation` / `ProblemCitation` 三张表各加一个 `AFTER DELETE` 触发器：删完如果父实体已无引用，把父实体 `status` 降回 `UNVERIFIED`。

**证明方式：** 给出这段序列的实际输出

### 6.1 结论

### 6.2 理由（按重要性）

1. **pgvector 在 Windows 原生装是自找麻烦。** Linux 一行 `apt install`，Windows 要 MSVC 编译。`pgvector/pgvector:pg16` 镜像把整个坑绕掉。
