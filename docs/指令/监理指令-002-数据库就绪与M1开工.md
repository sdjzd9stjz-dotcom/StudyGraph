## 2. 必须先修的三项

### 2.1 【P1-1】纯函数与 SQL 的下游语义不一致

**实测证据（我在 PG16 容器上跑的，不是 PGlite）：**

`downstream.sql` 里写死 `AND e.kind = 'DERIVED_FROM'`，而 `dag.ts` 的 `collectDownstream` 默认 `kinds ?? EDGE_KINDS`（三种全走）。

```js
collectDownstream([A --CITES--> B], 'A')  →  ['B']
SQL 版（只走 DERIVED_FROM）              →  []
```

**这不是性能差异，是行为差异。** 文件头写的"互为验证"目前不成立。

**判定：P1。** M2 的 stale 传播会直接踩上去，而且踩上去时两边各自都"对"，极难发现。

**要求：**

1. **明确 stale 传播沿哪些 `EdgeKind` 展开**，写进 `docs/architecture.md` 新的一节，并给出理由
   - 我的判断（**供参考，不是命令**）：`CITES` 是"引用原文"，不构成加工依赖；`PREREQUISITE` 是概念先修，不构成节点图上的数据流。所以 stale 传播**应该只沿 `DERIVED_FROM`**。
   - 但这是我的推断，不是规格明文。**你要么采纳并写理由，要么给出相反论证。不要沉默。**
2. 让纯函数与 SQL 的默认行为一致（改哪边都行，但要一致）
3. 加**跨实现等价性测试**：同一张图，纯函数结果与 SQL 结果必须 `deepEqual`

**证明方式：**

```bash
# 同一张图，两边跑，结果必须一致
docker exec studygraph-postgres psql -U studygraph -d studygraph -f packages/db/sql/downstream.sql -v start='<nodeId>'
node apps/api/test/unit/dag.test.ts        # 新增等价性用例应通过
```

报告里贴：构造的图（含 CITES / PREREQUISITE 边）+ 两边的原始输出。
